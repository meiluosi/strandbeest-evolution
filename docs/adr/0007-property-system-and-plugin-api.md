# ADR-0007: 属性系统与扩展 API

**状态：接受（2026-10-06，按推荐方案）** · 单向门 #8、#9

**背景** 每个新节点类型现在要手写：schema、构建器、界面表单、API 校验、文档。扩展点（地形、风、驱动、指标）只在 Python 仿真侧有，无版本、无清单。

**选项**
1. 现状：逐个手写。
2. **属性系统**：每种节点/资产用 JSON Schema + UI 注解（`x-unit`、`x-range`、`x-group`、`x-doc`、`x-assumption`、`x-calibratable`、`x-affects`）声明一次，生成：编辑表单、API 校验、MCP 工具 schema、文档、缓存失效规则。
3. 独立的 TS/Python 声明，再生成 schema：类型更强，但多一层生成工具。

**推荐** 方案 2 起步（和现有 `schemas/` 衔接最好）；若注解逐渐复杂再考虑方案 3。

**扩展 API** 枚举扩展点（节点类型、物理后端、地形、风、指标、优化器、导入器、导出器、面板、MCP 工具）；插件清单含 `api_version`、依赖、能力、权限；加载时检查兼容。**内置功能走同一套扩展点**。硬规则：扩展**不得绕过操作系统**改设计。

**后果** `schemas/` 增加注解；界面表单逐步改为由属性声明渲染；仿真注册表升格为带版本的扩展点。

**验证** 新增一个节点类型（例如弹簧）只写一份声明，界面、API、工具、文档自动出现；插件在不兼容的 `api_version` 下被明确拒绝而不是悄悄出错。
