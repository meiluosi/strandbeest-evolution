# ADR-0009: 运动学的唯一真相来源

**状态：接受（2026-10-06）—— 先保持双实现，用数据盯住触发线** · 单向门 #13

**背景** 二元组求解器和步态指标在 TS（设计器实时用）和 Python（服务端、制造、仿真用）各有一份，设计模型也有两份。靠共享的契约语料库（`contracts/kinematics/`）对齐。规模变大（拓扑编辑、约束求解）后，重复实现会增加，漂移风险上升。

**选项**
1. 双实现 + 契约语料库（现状）：成本低；每个重复模块都是一份维护负担。
2. 一份 Rust 内核，编译成 WASM 给浏览器、用绑定给 Python：一份真相；构建链和贡献门槛上升，需要 Rust。
3. 浏览器里用 Pyodide 跑 Python 内核：一份真相；体积和启动慢，实时拖动的延迟未知。
4. 只留 TS 或只留 Python：只留 Python 失去浏览器实时反馈，只留 TS 失去制造/仿真生态。

**决定** 现在选 1，但**把触发线变成可检查的东西**：`contracts/duplicated-modules.json` 列出所有重复模块和各自的语料库，`scripts/check_duplication_trigger.py`（进 CI）在以下任一成立时报失败，从而触发对 2/3 的评估：
- 重复实现的模块超过 **3 个**；
- 记录到第 **2 次**"两边答案不一致"的事故（`incidents_of_disagreement`）。

**后果** 每新增一个重复模块必须登记并配语料库；语料库是**测试资产**，不是实现的副产品；新增非 Jansen 设计到语料库是低成本的强测试。

**验证** 语料库在 TS 与 Python 两侧都通过（已做：4 个设计，其中 3 个非 Jansen 或非默认）；触发线检查通过（现在 3 个模块、0 次事故）。

## 触发线评估（2026-10-06）

**触发了。** E2、E3 把 `ids`（ULID）、`structure-validity`（静态有效性）、`edit-algebra`（操作 + 有效性守门 + JSON 补丁）三个模块在 TS 和 Python 两边都实现了，加上原有的 3 个，重复模块 = **6 个**，超过线（3）。按本 ADR 的约定，这意味着对选项 2/3 做评估，而不是默默改线。评估如下。

**事实**
- 0 次"两边答案不一致"的事故。契约语料库把每个重复模块都钉住：运动学 4 个设计、180 个采样点（1e-9）；ULID 40 行 + 参考实现的公开样例；静态有效性 13 个用例；操作 34 个用例（逐字节相同的 JSON 补丁或相同的拒绝原因，含 `branch_flip` 与 `cannot_assemble` 的边界）；设计 v1→v2 迁移两边得到同一份文档。
- 新增的三个模块都是**对 JSON 的确定性纯函数**，没有数值积分、没有随机性；唯一数值上敏感的是有效性守门（72 个采样点 + 16 倍细化），语料库里放了两侧都过的边界用例。
- 两侧都真正需要：浏览器编辑器要立刻响应（不能每次拖动都等服务器往返；设计页现在不需要后端），而智能体/MCP、优化库、制造和仿真都在 Python。
- 这三个模块写两遍的实际成本：每个约 150–250 行 + 一份语料库生成脚本；生成语料库的脚本只用 Python 实现，TS 只当运行器，所以"改一个行为"要改两处代码、重生成一次语料库。

**选项评估**
- 选项 2（Rust → WASM + Python 绑定）：能一次性统一求解器、步态、有效性、守门、操作。成本是构建链、贡献门槛和调试体验；现在没有事故支撑这笔投入。
- 选项 3（浏览器里跑 Pyodide）：体积大、启动慢，实时拖动的延迟没有测过。
- 选项 4（只留一侧）：失去浏览器的实时反馈或 Python 的制造/仿真/智能体生态。

**决定** 继续双实现，把线从 3 提到 **6**（刚好等于现在的数量，**下一个重复模块就会再次触发**）；`contracts/duplicated-modules.json` 增加 `limit_history`，改线必须带理由，检查脚本会验证。再次评估的条件（任一）：
1. 出现第 7 个重复模块；
2. 出现第 1 次"两边答案不一致"的事故（原线是第 2 次，现在更早）；
3. 操作类型超过约 15 种，或引入约束求解器 / 拓扑综合（那时写两遍的成本会陡增）。

**这是一个我替你做的决定**：如果你更想现在就开始做 Rust/WASM 内核，改 `max_duplicated_modules` 回 3 即可让 CI 重新报警，并把选项 2 排进任务卡。
