# ADR-0004: 确定性、状态快照、出处与缓存

**状态：接受（2026-10-06，按推荐方案）** · 单向门 #4、#10、#14

**背景** 想要"在编辑器里仿真"（暂停、检查、改参数、分叉）、可复现的运行、内容寻址缓存、复现包，这些都建立在同一个地基上：仿真的**状态可保存/恢复**，运行有**明确的输入键**。

**选项**
1. 现状：运行记录里有完整配置和代码版本，但没有输入哈希，没有快照接口。
2. 仿真接口含 `reset(seed)`、`step(n)`、`snapshot()`、`restore(snap)`；每个运行记录 `(设计哈希, 世界哈希, 后端名+版本, 平台, 种子)`；缓存键 = 这五项的哈希。
3. 只保证逐位复现：做不到（跨 CPU 的浮点差异），承诺会失信。

**推荐** 方案 2，并**明说**承诺的范围：同输入同平台在数值容差内一致；跨平台不保证逐位一致。出处记成 DAG：产物节点（ID + 输入哈希）和"派生自"边。

**两种回放并存** 状态录像（现在有）与**输入日志重放**（设计哈希 + 世界哈希 + 种子 + 外部输入，如阵风时刻），后者体积小、可重新求值。

**作业** 从单个升级为 DAG；ask/tell 接口服务优化器；缓存失效由属性系统的 `affects` 驱动。

**验证** 同输入两次运行结果在容差内一致；`snapshot→restore→继续` 与不间断运行的结果在容差内一致；命中缓存时不重跑；"这个数怎么来的"能沿 DAG 回答到设计与场景。
