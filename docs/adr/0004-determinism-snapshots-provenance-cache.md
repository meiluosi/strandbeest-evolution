# ADR-0004: 确定性、状态快照、出处与缓存

**状态：接受（2026-10-06，按推荐方案）** · 单向门 #4、#10、#14

**背景** 想要"在编辑器里仿真"（暂停、检查、改参数、分叉）、可复现的运行、内容寻址缓存、复现包，这些都建立在同一个地基上：仿真的**状态可保存/恢复**，运行有**明确的输入键**。

**选项**
1. 现状：运行记录里有完整配置和代码版本，但没有输入哈希，没有快照接口。
2. 仿真接口含 `reset(seed)`、`step(n)`、`snapshot()`、`restore(snap)`；每个运行记录 `(设计哈希, 世界哈希, 后端名+版本, 平台, 种子)`；缓存键 = 这五项的哈希。
3. 只保证逐位复现：做不到（跨 CPU 的浮点差异），承诺会失信。

**推荐** 方案 2，并**明说**承诺的范围：同输入同平台在数值容差内一致；跨平台不保证逐位一致。出处记成 DAG：产物节点（ID + 输入哈希）和"派生自"边。

**两种回放并存** 状态录像（现在有）与**输入日志重放**（设计哈希 + 世界哈希 + 种子 + 外部输入，如阵风时刻），后者体积小、可重新求值。

**作业** 从单个升级为 DAG；ask/tell 接口服务优化器；缓存失效由属性系统的 `affects` 驱动。

**验证** 同输入两次运行结果在容差内一致；`snapshot→restore→继续` 与不间断运行的结果在容差内一致；命中缓存时不重跑；"这个数怎么来的"能沿 DAG 回答到设计与场景。

## 实现核对（2026-11-03，H1-01 / H1-05）

MuJoCo 的编译模型包含可修改的重力、接触和执行器参数，因此不能仅复制积分态并把模型当作不可变对象共享。分叉现在复制编译模型与完整数据（无需重新编译 MJCF），且场景配置独立；隔离回归同时检查父、兄弟与后代分支。

固定参数下的快照续跑测试不能证明参数编辑可回滚。H1-05 现已将会话快照扩展为独立复制的场景、完整模型/数据和驱动状态；每次恢复再次复制保存的世界，并按恢复的配置重建确定性风函数，防止闭包继续引用旧配置。定向测试覆盖参数编辑、风帆执行器释放及重复恢复（EXPERIMENTS §47）；后续整树常规与适用慢检查已通过（EXPERIMENTS §49）。快照仅为进程内版本 2 对象，不声称可序列化、跨版本迁移或断电持久化。后端级积分检查点保持其原有窄语义。气动状态的同类要求保留在 H3-02。

## 缓存身份修订（2026-11-04，H1-06）

原五元组遗漏了 Beest 自身算法：在 MuJoCo 版本相同而能量、观测、事件或证据算法改变时，可能复用旧结果（EXPERIMENTS §52）。新运行使用版本 2 输入键：在原五项上加入 `key_format`、`simulation_semantics` 和 `implementation_hash`。代码版本标签仍用于展示，不能代替实现身份。

实现哈希来自实际安装的 common/sim/API 源码与数据、JSON Schema、Rust 原生扩展字节，以及 Python/数值依赖版本和计算线程环境。文件名相对安装目录，不依赖 git、绝对路径或文件时间。语义标签覆盖能量、观测、事件、证据及多配置汇总；即使忘记修改标签，文件内容变化仍使键失效。这是保守失效：注释及无关 API 文件变化也可能令结果重新计算。

在 common 初始化的最前端保存进程对应的文件清单；每次读取缓存及计算结束时重新核对内容和新增/删除的文件。已经发现文件或依赖变化的进程必须重启才能恢复复用，不能用新文件的哈希标记仍在内存执行的旧实现。受检查的函数、方法、常量和注册插件若运行时改变，也停止复用。这个检查服务于正常安装与开发流程，不是针对任意内存修改或伪造运行文件的安全边界；未登记的动态扩展不获得缓存兼容承诺。

`Run.provenance.execution_identity` 记录核验状态、哈希与清单，无法核验时记录原因且不写 `input_key`。仿真仍可运行。它对旧 v1/v2 运行是可选字段；迁移与重建索引不得补写当前实现或重算历史输入键。SQLite 只提供候选，API 必须再比较实际 Run 的身份与输入/后端字段。历史文件保持可读且不因命中缓存而改写。验证覆盖真正的独立进程重启、无 git 的安装布局、相同版本标签/时间下的源文件修改、旧记录与不可核验实现。

校准应用增加 `Run.provenance.calibration_profile_id`。输入键仍由解析后的实际物理场景决定，但复用候选还必须匹配 Profile 引用；物理参数恰好相同不能把无校准来源的旧 Run 改标成新的校准结果。重建索引恢复 Run→Profile→Measurement 关系。测量上传或内联校准遇到相同 ID 的不同内容返回冲突，避免原始证据被后来上传覆盖（EXPERIMENTS §55）。
