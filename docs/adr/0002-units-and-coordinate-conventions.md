# ADR-0002: 单位、坐标系与符号约定

**状态：提议（等待拍板）** · 单向门 #2

**背景** 项目已经因为约定踩了三次坑：接触刚度的单位（N/m 其实是 1/s²）、长度单位（线性机构的"单位"与毫米、米）、曲柄角的符号（逆时针 θ 与 MuJoCo 绕 +y 的铰链顺时针，行走方向 ψ）。三维里 MuJoCo（x 前、z 上）与 three.js（y 上）还各有一套轴。

**选项**
1. 保持现状，靠注释：已经出过事故。
2. 引擎边界一律 SI（米、千克、秒、弧度、N·m）；字段名带单位后缀；一份**坐标系与符号约定**文档，用测试固定。
3. 引入带量纲的类型（如 pint）贯穿全栈：最安全，但成本高、跨 TS/Python 难。

**推荐** 方案 2，并在**属性系统**里给每个数值字段声明单位，界面和 agent 工具由此显示单位；方案 3 只在 Python 内部关键计算里按需用。

**约定草案**
- 世界系：右手，x 前进、y 横向、z 向上；2D 连杆的髋关节系为 (x 前, y 上)。
- 曲柄转角 ψ：沿**行走方向**为正；θ（连杆求解用的逆时针角）= `direction × ψ`；MuJoCo 铰链角 q = −θ。
- 时间：仿真时间（秒）与墙钟时间分开命名。
- 连杆长度单位 `unit_m`（米/单位）是设计的显式字段，不是隐含常数。

**后果** 要写一份约定文档并加"约定测试"（例如：给定 ψ 增量，三处实现的脚前进方向一致）。三维视图里的轴映射集中在一个函数里。

**验证** 约定测试覆盖 TS 求解器、Python 求解器、MuJoCo 构建器、three.js 映射。
