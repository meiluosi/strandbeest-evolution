# ADR-0013：以研究工作台增量演进现有 Svelte 前端

状态：**接受**（2026-11-06，用户认可研究旅程与整体前端重构建议并要求推进）。本决定确定产品前端架构与实施边界，不表示 Harness 后端、模型训练、评测或科学证据已经实现。

## 背景

现有 `apps/web-demo` 已完成 Strandbeest Studio 的设计、演化、仿真与回放工作台改造，并保留制造、数字海滩、实验室、静态烘焙和浏览器 WASM 路径。3D 回放另有独立的“潮汐巨构”环境美术层。上述能力是当前基线，不是需要丢弃的概念原型。

Beest Model Experiment Harness 将产品目标扩展为物理世界模型与具身智能研究的实验编排、模型训练、仿真验证和证据管理。用户需要完成“研究问题 → 冻结数据 → 训练与评测 → 预测回放 → 限定结论”的连续旅程。仅在现有三个工具页旁追加表格或 Dashboard，无法表达实验修订、数据快照、任务 Attempt、模型制品和证据之间的关系。

## 选项

1. **保留工具页结构，只追加 Harness 面板。** 改动较小，但研究对象、执行状态和证据继续分散，无法形成可理解的跨页面上下文。
2. **另建前端或更换技术栈。** 可以重新组织视觉，但会重复 Design、GA、Replay、i18n 和静态模式，增加事实源分裂与迁移风险。
3. **保留 Svelte 和领域工作台，增量重构为研究工作台。** 以研究旅程组织新能力，以现有设计、演化、仿真页面作为领域工作台；通过真实 API 投影接入 Harness，不建立平行科学数据层。

## 决定

采用方案 3，具体约束见 [Harness 前端目标架构](../HARNESS-FRONTEND.md)。

- 前端继续使用 Svelte 5 与现有构建、测试和 i18n 体系；不为本次改造更换框架或复制 Three.js、几何、物理与 GA 内核。
- 全局 Shell 从单一“当前设计”上下文扩展为“研究项目／实验／修订 + 当前设计”上下文；没有实验时，独立设计和小型复验仍可使用。
- 新研究旅程分为实验设计、运行与回放、比较与证据三个关联视图。既有设计、演化、仿真、制造、数字海滩和实验室继续可发现、可深链。
- 服务端是 Experiment、Job、Attempt、Artifact、Evaluation 与 Claim 的事实来源；前端只持有编辑草稿、查询视图和 UI 偏好。不得用浏览器内存或静态样例冒充持久化执行状态。
- 新增 `/api/harness/v1` 的视图适配层，保持旧 API 语义。Schema、ID、单位、来源和证据规则复用公共契约，不由 UI 另行定义科学语义。
- 视觉延续“精密机械图纸 + 现代实验仪器”，允许在 3D 场景中使用克制的异星海滩与巨构美术；不把研究界面做成赛博大屏或等权卡片集合。
- HN06 拆为 `HF-00` 至 `HF-08`。M1 只要求真实手动实验链路；受控 Research Agent 界面依赖 HN07，不能提前宣称完成自主研究。

## 后果与迁移

- 现有 `?tab=design|evolve|sim|fab|beach|lab` 深链必须继续工作；新增研究深链采用显式对象与修订引用，不能通过 `latest` 恢复科学输入。
- 主题、语言和面板偏好与 Design Operation、ExperimentRevision 分开持久化。全局状态只在确有跨工作区共享需求时提升，不建立包罗万象的前端 Store。
- 新界面可先使用明确标注的契约样例开发组件，但合并验收必须连接真实执行结果；静态站点只展示真实已有资产，并禁用或解释写入、训练和审批能力。
- 后端能力未就绪时，前端可以完成 Shell、设计系统、现有工作台和只读空态；不得以假数据填满页面来消除依赖。
- 旧 Design、Scenario、Run、Measurement、Profile 与既有回放保持可读。前端重构不改变物理参数、证据等级、缓存身份或历史结果。

## 验证

- 每个 HF 任务卡按 `ACTIONS.md` 的 Definition of Done 提供测试与证据；组件通过不等于真实研究链路通过。
- 完整矩阵覆盖 live/static、中英文、明暗主题、375/768/1024/1440 像素、键盘、减少动态效果、断线重连和控制台／资源错误。
- M1 浏览器验收必须使用真实来源轨迹、冻结 Snapshot、实际模型权重和真实评测输出，完成协议、运行、预测叠加、异常追溯和限定结论。
- 没有提升、失败、证据不足和未验证均需有可读的界面出口；绿色执行状态不能替代科学证据。
