# ADR-0008: 项目文件格式与国际化

**状态：提议（等待拍板）** · 单向门 #11、#12

**背景** 项目将来要能 git、要分享、要打包复现。界面现在有 11 个文件写死了中文；项目数据散在 `data/` 的文件夹和一个 SQLite 里。

**选项（项目格式）**
1. 现状：运行和设计散落，SQLite 里也有元数据。
2. 项目 = 文件夹 + `project.json`；资产是**文本 JSON，键排序稳定**；`runs/` 内容寻址；`derived/` 缓存不入库；数据库**只做索引和缓存**，可以从文件重建（我们已经这样做了运行索引）。
3. 全放数据库：难以 git、难以分享。

**推荐** 方案 2。大二进制走 Git LFS 或内容寻址目录。

**选项（i18n）** 现在改（界面字符串走消息目录键，中英两份）还是以后统一抽取？抽取的成本随界面数量线性增长，且会漏。**推荐现在做**：选一个轻量的消息目录方案（ICU 消息格式），规定新增界面不得写死字符串；文档保持双语流程。

**后果** 增加项目加载/保存层；界面逐文件改造；CI 检查源码中不应出现硬编码字符串（白名单例外）。

**验证** 项目文件夹复制到另一台机器能直接打开且结果一致；切换语言后界面无遗漏字符串；对同一设计两次保存的文本输出逐字节一致（稳定排序）。
