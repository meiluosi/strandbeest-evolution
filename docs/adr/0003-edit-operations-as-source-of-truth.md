# ADR-0003: 编辑操作日志作为设计的真相来源

**状态：提议（等待拍板）** · 单向门 #3

**背景** 设计要被人、遗传算法、AI agent、强化学习策略共同修改，还要撤销、谱系、可复现。现在设计是一份被整体覆盖的 JSON。

**选项**
1. 状态为真相（现状）：简单；无法撤销到任意点、无法记录"谁为什么改"、无法合并。
2. 操作日志为真相，状态是日志的折叠结果，周期性快照做缓存。
3. 直接上 CRDT：支持并发合并，但复杂度高，当前没有并发编辑的需求。

**推荐** 方案 2：线性历史 + 分支；合并先做"变基"；并发多人/多 agent 出现时再升级。

**操作的形状** `{id, type, args, actor{kind: human|algorithm|agent, id}, reason, timestamp}`，每个类型实现 `apply(design)` 与 `inverse()`；类型清单见 VISION §3.2（`add_dyad`、`set_param`、`array_legs` 等）。

**后果** 设计文件存"初始设计 + 日志"或"最新状态 + 日志"（两者可互相重建）；谱系树 = 日志分叉图；遗传算法的变异/交叉实现成操作序列；MCP 工具由操作定义自动生成。

**验证** 属性测试：`apply(op); undo()` 恒等于原设计；`replay(log)` 恒得到同一设计；随机操作序列下求解器的"有效性守门"不放过无效设计。
