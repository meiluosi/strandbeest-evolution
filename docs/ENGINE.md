# 引擎化蓝图：做一个聚焦于"风力步行机构"的"虚幻引擎"

> 这份文档回答一个问题：**如果这个项目要长成一个引擎（运行时 + 编辑器 + 内容管线 + 插件 + 云端服务），哪些东西现在不定下来，以后一定返工？**
> 方法：把虚幻引擎（UE）的子系统逐个映射到我们的领域，挑出**单向门**（一旦做错就要大改的决定），标出**现在该定、可以晚点定、不该做**的三类。
> 配套：决定记录在 [adr/](adr/)（0001–0008 已于 2026-10-06 接受）；任务在 [ACTIONS.md](ACTIONS.md)；产品形态在 [VISION.md](VISION.md)；平台阶段在 [PLATFORM.md](PLATFORM.md)。

## 0. 定位：像 UE，但不是 UE

**我们借 UE 的是架构，不是功能清单。** UE 的价值是：一个无头的**运行时**，上面坐着一个**编辑器**，中间有**资产管线**、**撤销/重做**、**反射式属性系统**、**插件模块**、**派生数据缓存**、**打包**、**分析工具**。这些东西让内容、工具、运行时能各自演化而不互相打碎。

| 我们要借 | 我们**不**借 |
|---|---|
| 资产与引用、属性系统、事务（撤销）、插件、缓存、打包、分析工具、"在编辑器里玩"（PIE）、实时数据接入（Live Link） | 照片级渲染（PBR、光追）、骨骼动画、游戏玩法框架、音频、多人联机、商店支付、主机认证 |

我们的"画质"是**物理保真度和可复现性**，不是像素。

一句话定义：**Beest Engine**（暂名）= 一个无头的"设计 → 仿真 → 制造 → 测量"运行时，加一个以它为后端的编辑器，加一套让人、算法、AI agent 平等使用的接口。

## 1. UE 概念 → 我们的对应物

| UE 的东西 | 它解决什么 | 我们的对应物 | 现状 | 何时定 |
|---|---|---|---|---|
| **Asset / GUID / 引用** | 内容之间稳定地互相指向 | 设计、场景、运行、测量、校准结果、导出包都是资产，带稳定 ID | **按名字引用**（`design_name`） | **现在**（ADR-0001） |
| **Content Browser** | 浏览、搜索、缩略图 | 资产浏览器；设计和运行自动生成缩略图（渲染一帧） | 无 | 稍后 |
| **Level / World** | 场景 = 一组 Actor | **World**：地形、风场、大气、重力 + 若干**实体**（步行者实例、障碍、风源） | 场景 = 单步行者 + 地形 | **现在**（ADR-0005） |
| **Actor + Component / ECS** | 组合式对象；海量实例（Mass Entity） | 步行者 = 实体 + 组件（连杆、驱动、帆、机身、传感器、气动大脑）；**兽群**要靠它 | 仿真器只会造一个躯干 | **现在**（数据模型）；兽群实现晚 |
| **Details Panel / UPROPERTY（反射）** | 声明一次属性，自动得到编辑界面、序列化、脚本接口 | **属性系统**：每种节点声明属性（含单位、范围、文档），自动生成表单、API 校验、MCP 工具 schema、文档 | 界面逐个手写 | **现在**（ADR-0007） |
| **Transaction / Undo** | 所有修改可撤销、可记录 | **编辑代数 + 操作日志**（VISION §3.2） | 无 | **现在**（ADR-0003） |
| **Blueprint（可视化脚本）** | 非程序员定义行为 | **实验图**：用节点连出"设计 → 扫描 → 仿真 → 分析 → 报告"；以及给 agent 的脚本 API | 无（有扫描接口） | 中期 |
| **Chaos / PhysX（物理后端）** | 可替换的物理 | **PhysicsBackend 接口**，MuJoCo 是第一个实现；将来可接 Chrono（地面力学）、自研的气动/气路 | 直接调用 MuJoCo | **现在**（接口，ADR-0005） |
| **Play In Editor（PIE）** | 在编辑器里直接跑、暂停、弹出控制 | **在编辑器里仿真（SIE）**：暂停 → 检查 → 改参数 → 从这一帧继续 / 分叉（VISION §2 的 L3） | 无 | 中期，但**状态快照接口现在要预留** |
| **Replay System** | 录输入重放，省空间 | **输入日志重放**（设计哈希 + 场景哈希 + 种子 + 引擎版本）与**状态录像**两种并存 | 只有状态录像 | **现在**（ADR-0004） |
| **Sequencer** | 镜头、过场、动画渲染 | **报告与镜头**：相机路径、带标注的回放、一键导出 mp4/gif/图、**自动生成可发表的报告**（你的博客就需要） | 手工 | 中期 |
| **Niagara（特效）** | 粒子与场的可视化 | **场可视化**：风的流线、接触力箭头、应力热力图 | 无 | 中期（VISION §2 L1） |
| **Live Link** | 把外部设备数据实时灌进编辑器 | **测试台实时接入**：编码器、电流、风速实时显示并叠在仿真上（数字孪生） | 只有离线 CSV 导入 | 中期（设备抽象现在要想清） |
| **Derived Data Cache** | 昂贵的派生数据只算一次 | **内容寻址的计算缓存**：键 = 设计哈希 + 场景哈希 + 后端版本 + 代码版本 | 无（每次重跑） | **现在**（ADR-0004） |
| **Cooking / Packaging** | 把项目打成可发行包 | **导出**：打印包、复现包（设计 + 场景 + 数据 + 容器）、独立 HTML 查看器（内嵌回放） | 只有打印包 | 中期 |
| **Plugins / Modules + API 版本** | 第三方扩展而不 fork | 扩展点：节点类型、物理后端、地形、风、指标、优化器、导入器、导出器、面板、MCP 工具；**带版本号的扩展 API** | Python 注册表（仅仿真侧） | **现在**（清单 + 版本号，ADR-0007） |
| **Unreal Insights（性能分析）** | 看每帧耗时 | **仿真分析器**：步时、求解器迭代、接触数、约束违反量、不变量面板（能量、守恒量） | 零散指标 | 中期 |
| **Automation / Gauntlet（自动化测试）** | 大规模回归 | **基准与回归库**：金标运行、数值回归、视觉回归、编辑操作的属性测试 | 单元测试 + 少量慢测试 | 持续 |
| **Source control 集成** | 协作 | 项目 = 文件夹 = git 仓库；**文本、可 diff、键排序稳定**的格式 | 部分（JSON） | **现在**（ADR-0008） |
| **Marketplace / Fab** | 资产分享 | **Commons**：设计注册表、谱系、带实测成绩的排行（VISION §4） | 无 | 晚 |
| **Datasmith（导入）** | 从其他软件导入 | **导入器**：STL/CAD、视频、CSV、第三方机构数据集 | 测试台 CSV | 稍后 |
| **Localization** | 多语言 | **i18n**：中英文消息目录 | **界面里写死中文**（11 个文件） | **现在**（ADR-0008） |

## 2. 单向门：现在不定，以后一定返工的 14 件事

> 判断标准：**错了以后要迁移已有数据，或者要改很多模块的接口。** 这些我都建议在写更多功能之前定下来（决定记录里每条都有选项、推荐和后果）。

| # | 决定 | 为什么是单向门 | 推荐 | ADR |
|---|---|---|---|---|
| 1 | **资产身份与引用**：名字还是稳定 ID | 所有文件互相引用；改了要迁移全部数据 | 稳定 ID（ULID/UUIDv7）+ 名字只做显示；不可变产物再加内容哈希 | 0001 |
| 2 | **单位与坐标约定** | 我们已经踩过：N/m 与 1/s²、mm 与 m、曲柄角符号 | 引擎边界一律 SI；字段名带单位；写一份**坐标系与符号约定**文档并用测试固定 | 0002 |
| 3 | **设计的真相来源：状态还是操作日志** | 决定撤销、谱系、agent、合并怎么做 | 操作日志为真相，快照为缓存；操作类型化、可逆、带执行者和理由 | 0003 |
| 4 | **确定性、状态快照、可复现键** | 决定 PIE、分叉、缓存、复现包 | 仿真接口含 `reset(seed)`、`snapshot()`、`restore()`；每个运行记录（设计哈希、场景哈希、后端版本、平台） | 0004 |
| 5 | **世界与实体模型** | 现在只能造一个躯干；兽群、风源、传感器都放不进去 | World + Entity + Component；单步行者只是 N=1 | 0005 |
| 6 | **物理后端边界** | 直接依赖 MuJoCo 的地方会越来越多 | `PhysicsBackend` 协议 + 一套**后端契约测试** | 0005 |
| 7 | **时间序列与几何的数据格式** | 现在是 npz；大运行、流式、跨语言会痛 | 遥测用 Arrow/Parquet，几何/场景用 glTF，元数据用 JSON；npz 作为旧格式导入 | 0006 |
| 8 | **属性系统（声明一次，处处生成）** | 否则每个新节点要手写表单、校验、工具、文档 | JSON Schema + UI 注解（单位、范围、分组、文档）；**表单、API、MCP 工具、文档全由它生成** | 0007 |
| 9 | **扩展点与扩展 API 版本** | 第三方和自己的插件都靠它 | 枚举扩展点；插件清单带 `api_version`；**任何扩展不得绕过操作系统改设计** | 0007 |
| 10 | **出处 DAG 与内容寻址缓存** | 决定"这个数怎么来的"能不能一键回答 | 每个产物 = 节点（ID + 输入哈希）；边 = 派生自；缓存键 = 输入哈希 | 0004 |
| 11 | **项目与文件格式** | 决定协作、版本控制、迁移 | 项目 = 文件夹 + `project.json`；资产是文本 JSON、键排序稳定；数据库只做索引/缓存 | 0008 |
| 12 | **i18n** | 每多写一个界面，返工成本就多一份 | 消息目录（zh/en）；界面字符串一律走键 | 0008 |
| 13 | **运动学的唯一真相来源** | TS 和 Python 各有一份求解器/步态指标，靠契约测试对齐，规模大了会漂移 | **先保持双实现 + 一套共享的契约语料库**；定一条"何时换"的触发线（见 §4） | 0009（待写） |
| 14 | **异步与流式协议** | 实时仿真、测试台直播、agent 都要它 | 带类型的事件流（WebSocket）；会话模型（`step/pause/set/fork`）；作业从"单个"升级为**DAG** | 0004 |

> 其余（渲染框架、前端状态管理、图表库、具体优化库）都是**双向门**，错了换掉就行，不在这张表里。

## 3. 目标架构

```
┌─────────────────────────────────── Agents / 脚本 / CLI（与编辑器同一套 API）───────────────────────────────────┐
│                                                                                                                │
│  Editor（客户端）                                  Services（服务端，可本地可远端）                               │
│  ├ Viewport（三维 + 叠加层 + 小工具）               ├ Job Graph（DAG 调度、缓存、重试、GPU 标签）                  │
│  ├ Asset Browser / Outliner / Details（属性系统）   ├ Simulation Sessions（实时/批量，快照与分叉）                 │
│  ├ Timeline / Sequencer / Report                   ├ Provenance + Cache（内容寻址）                              │
│  ├ Experiment Graph（实验图）                       ├ Live Link（测试台设备接入）                                  │
│  └ Profiler / Invariants                           └ MCP 工具面（由操作与属性系统自动生成）                        │
│                                                                                                                │
├──────────────────────────────────── Engine Runtime（无头，Python/TS，库）────────────────────────────────────────┤
│  Edit Algebra + Op Log  │  Design IR（图）  │  Kinematics/Assur 求解  │  Fab 规划  │  Optimizers  │  Calibration  │
│  World/Entity model  │  PhysicsBackend 接口 ──► MuJoCo │（Chrono│气动│…）│  Telemetry（Arrow/Parquet）            │
├──────────────────────────────────── Content（项目文件夹，文本，可 git）────────────────────────────────────────┤
│  project.json │ assets/（设计、场景、世界、实验图）│ runs/（内容寻址）│ data/（测量）│ derived/（缓存，不入库）  │
└────────────────────────────────────────────────────────────────────────────────────────────────────────────────┘
                 ▲ 插件（带 api_version 的扩展点：节点、后端、地形、风、指标、优化器、导入/导出、面板、工具）
```

**两条硬规矩**
1. **编辑器能做的，都是一次 API 调用**（命令行对等）。agent、脚本、CI 和人走同一条路。
2. **任何改设计的动作都必须是一个操作**（写日志、可撤销）。遗传算法、agent、插件、编辑器都不例外。

## 4. 各子系统（简述 + 决策点）

### 4.1 资产与项目
- 资产类型：`Design`、`Module`（可复用的腿/曲轴等）、`Scenario`/`World`、`ExperimentGraph`、`Run`、`Measurement`、`Profile`、`Report`。
- 引用 = `{id, (可选) version | hash}`；名字、标签、缩略图只是元数据。
- 项目文件夹：文本 JSON、**键排序稳定**、一行一个顶层项（diff 友好）；大二进制（Parquet、网格）走 LFS 或内容寻址目录；`derived/` 不入库。
- **迁移**：每个资产带 `schema_version`，迁移是显式函数 + 往返测试（已有雏形）。

### 4.2 属性系统（我们的 UPROPERTY）
一份声明同时给出：编辑表单、校验、序列化、MCP 工具 schema、文档。声明含：类型、**单位**、范围、默认值、分组、`assumption`（猜测值标记）、`calibratable`（可被校准）、`affects`（影响哪些派生数据 → 缓存失效）。
这是**最大的杠杆**：新增一种节点（比如"弹簧"）只写一次声明，其余全自动。

### 4.3 编辑与撤销
操作 = `{id, type, args, actor{kind,id}, reason, timestamp, inverse}`。线性历史 + 分支；快照每 N 个操作；合并先做"变基"，多人/多 agent 并发时再升级到 CRDT。属性测试：`apply(op); undo()` 恒等于原设计；`replay(log)` 恒得同一设计。

### 4.4 世界、实体与仿真
- **World** 是资产：地形（高度图/参数化）、地表（摩擦/软硬/沙）、大气（密度、风场随时间）、重力。
- **Entity** = 组件袋：`Linkage`、`Drive(sail|motor)`、`Body`、`Sensor`、`Brain`（远期）、`Marker`（视频追踪）。
- **PhysicsBackend 协议**：`build(world) → handle`、`step(n)`、`snapshot()/restore()`、`contacts()/forces()/energies()`、`set_param(path, value)`；**契约测试**：能量守恒、镜像对称、单位缩放不变、已知解析解（单摆、斜面滑块）。
- **会话**：`reset(seed)`、`step`、`pause`、`fork(from_frame)`、`set(param)`；输出事件流（落脚、打滑、被挡、停转）。
- **确定性承诺要写清楚**：同一组（设计哈希、世界哈希、后端版本、平台）→ 结果在数值容差内一致；**跨 CPU 不保证逐位一致**，不假装。

### 4.5 计算与缓存
- 作业从单个升级为 **DAG**（扫描 = 一批并行节点 + 汇总节点）；资源标签（CPU/GPU）；重试、取消、预算。
- **ask/tell 接口**给优化器（优化器请求一批候选，引擎评估后返回），这样换 CMA-ES、BO、QD 不用改引擎。
- 缓存键 = 输入哈希；命中直接复用，**失效由属性系统的 `affects` 驱动**。

### 4.6 数据
- 遥测（时间序列、接触力、能量项）：**Arrow/Parquet**，带模式，可流式追加，可按列读（回放只读需要的层）。
- 几何与场景：**glTF**（还能把回放存成 glTF 动画，用任何查看器打开）。
- 小元数据：JSON。npz 保留为**旧格式导入器**。

### 4.7 编辑器
- **Viewport**：渲染器抽象（现在 three.js）；叠加层系统；拾取、小工具、选择集；**无头渲染**（给 agent 和报告用：服务端出图出视频）。
- **PIE（在编辑器里仿真）**：暂停 → 检查 → 改参数（热更新）→ 继续或分叉。
- **Timeline/Sequencer**：事件轨、足迹图、相机路径、标注、一键导出。
- **Experiment Graph**：节点式实验；每个节点是引擎作业；整个图可保存、可重跑、可分享。

### 4.8 扩展点（插件）
节点类型、物理后端、地形、风、指标、优化器、导入器、导出器、面板、MCP 工具。每个扩展声明 `api_version`、依赖、能力、权限；**加载时检查兼容**。内置功能也走同一套扩展点（"吃自己的狗粮"），这是防止 API 腐烂的最有效办法。

### 4.9 实时设备接入（Live Link）
测试台作为**设备**：声明通道（编码器、电流、风速…）、采样率、单位、校准文件；编辑器实时显示并叠在仿真上；录下来就是 `Measurement`。设备抽象现在不做完，但**测量格式要和它一致**（已经基本一致）。

### 4.10 运动学的唯一真相来源（单向门 #13，单独说）
现状：同样的二元组求解器和步态指标，TS 一份（设计器实时用）、Python 一份（服务端、制造、仿真用），靠共享契约测试对齐。
选项：A 双实现 + 契约语料库（现状）；B 一份 **Rust 内核** 编译成 WASM 给浏览器、再用绑定给 Python；C 浏览器里用 Pyodide 跑 Python 内核；D 只留 TS 或只留 Python。
**推荐**：先 A，但把契约语料库（一批设计和期望的轨迹/指标）独立成资产，所有实现都必须过它。**触发线**：出现第二次"两边答案不一致"的事故，或者需要重复实现的模块超过 3 个（拓扑编辑和约束求解很可能触发），就评估 B。不要现在为了"洁癖"重写。

## 5. 现状盘点：哪些已经对齐，哪些会冲突

| 方面 | 已经对齐 | 会冲突/要改 |
|---|---|---|
| 数据契约 | `schemas/` 里有 Design/Measurement/Profile/Run；带 `schema_version` | **Scenario 没有 JSON Schema**（pydantic 是真相）；引用靠名字 |
| 扩展点 | 仿真侧有注册表（地形、风、驱动、指标） | 只有 Python 侧；无版本号；TS 侧没有 |
| 作业 | 持久化队列、取消、重启恢复、扫描 | 不是 DAG；无缓存；无资源标签 |
| 出处 | 运行记录有代码版本、引擎版本、完整配置 | 没有输入哈希；没有出处图；无法"一键问为什么" |
| 仿真 | 无头、可批量、可回放 | 直接耦合 MuJoCo；只造单个躯干；无快照/分叉；无事件流 |
| 数据 | npz + JSON | 无模式、不可流式；回放读整个文件 |
| 设计 | 求解器/步态/制造/仿真构建已是通用的二元组链 | 查看器、滑块、基因、3D 预览写死 Jansen；无操作日志；无撤销 |
| 界面 | 四个标签页，设计系统，3D 回放 | **11 个文件里写死中文**；每个面板手写；无命令系统 |
| 坐标/单位 | 构建器文档里写了曲柄角约定 | 没有统一文档；three.js 与 MuJoCo 各有一套轴；已出过单位事故 |
| 测试 | 单元 + 少量慢测试 + 交叉验证脚本 | 没有操作的属性测试、金标运行库、视觉回归、后端契约测试 |

**好消息**：数据契约、注册表、持久化作业、出处字段这四块是引擎的骨架，已经有了，只需要"升格"而不是重写。

## 6. 迁移顺序（最少返工）

> 原则：**先定约定与接口（几乎不写功能代码），再按依赖逐层替换。** 每一步都保持现有功能可用。

| 步 | 内容 | 动到哪里 | 返工风险 |
|---|---|---|---|
| E0 | **定 ADR 0001–0008**，写《坐标系与符号约定》，抽出**运动学契约语料库** | 文档、测试 | 无（只定规矩） |
| E1 | **i18n 与属性系统声明**：界面字符串走键；先给 `Design`/`Scenario` 的字段补单位/范围/假设标记注解 | 11 个界面文件、schema | 低，但越早越省 |
| E2 | **资产 ID**：所有资产加 `id`，引用改成 `{id}`，保留名字→ID 的迁移器 | schema、API、存储 | 中（迁移一次，之后稳定） |
| E3 | **规格驱动化 + 编辑代数 v0 + 操作日志 + 撤销**（VISION §7 第 1、2 步） | 查看器、滑块、基因、3D | 中 |
| E4 | **世界/实体模型 + PhysicsBackend 接口 + 快照/分叉**：把 MuJoCo 包进后端，构建器接受 N 个实体 | `packages/sim` | 中高（但被隔离在一个包里） |
| E5 | **出处 DAG + 内容寻址缓存 + 作业 DAG** | `apps/api` | 中 |
| E6 | **Parquet/glTF 遥测与场景**；npz 转旧格式导入器 | sim 输出、API、播放器 | 中 |
| E7 | **扩展 API v1**：把现有注册表升格（清单 + 版本），内置功能走同一套 | sim、core | 低 |
| E8 | **MCP 工具面（由操作与属性自动生成）**、PIE、Live Link、Sequencer、Profiler | 各处 | 取决于前面是否做对 |

**如果只能先做三件事**：E0（零代码，纯约定）、E2（资产 ID，越晚越贵）、E3（编辑代数，整套设计的支点）。

## 7. 防止"过度工程"的护栏

UE 是几千人做了二十年的东西。我们要避免两个极端：**什么都不定导致返工**，和**什么都先做导致永远发不出东西**。

1. **只把"单向门"做成架构；双向门写成代码就行。**
2. **每个子系统先做"最小可用 + 可替换的接口"**：比如缓存先用本地文件夹，只要键的定义对了，以后换对象存储不改上层。
3. **吃自己的狗粮**：内置功能走扩展点；否则 API 一定会烂。
4. **每个新子系统带验证门槛**：能量账闭合、`apply+undo=恒等`、后端契约测试……不过门槛不合并（我们这几周靠验证抓到了三个 bug）。
5. **随时问"这对步行机构有用吗"**：渲染、动画、联机这些，我们不做。
6. **保持可以单机、可以离线、可以 git**：这个项目面向开发者和爱好者，不是 SaaS。
