# 产品形态：这个东西最终可以长成什么

> 这是一份**想象力文档**，不是承诺。每个想法都标了：它建立在仓库里已有的什么上、还缺什么、最大的风险是什么。越往后越科幻，也越需要先有真实数据。
> 一条贯穿始终的原则：**科学上的诚实本身就是产品功能**。界面永远显示"这个数有多不确定、来自哪一层"，而不是一个漂亮的单值。

## 0. 先看我们已经有的

一个闭环：**设计 → 仿真 → 3D 打印 → 测量 → 校准 → 再设计**，前面四步有了薄薄的实现，最后两步在等真实数据。再加上最近的几块：3D 回放、场景库（地形、风、阵风、其他星球的重力和空气密度）、可扩展的仿真器（注册表）、带质量报告的测量导入。

所以"形态"的问题不是"做什么"，而是"这条闭环对谁、在哪个尺度上、能走多远"。下面从近到远分七层。

---

## 1. 近：一个可信的工作台（半年内）

**Studio（设计工坊）。** 现在的网页已经是雏形：设计、制造、仿真、实验室四个标签。近期要把它打磨成"一个爱好者一晚上能从零做出一只会走的小动力兽"的体验：
- 向导式流程（选腿数和尺寸 → 看步态 → 看会不会走 → 导出 → 装配说明带图）。
- 每个数字旁边标来源和不确定度（假设、简化模型、仿真、实测，四种颜色的小标记）。
- **装配说明变成 3D 动画**：现在有 ASSEMBLY.md 和 3D 预览，下一步是分步爆炸图。

**价值：** 把"我不知道会不会走"变成"我知道它大概怎么走、哪里没把握"。
**缺什么：** 真实打印的反馈（最缺）。**风险：** 导出的零件假设太多，第一版会不合用。

## 2. 近：场景库和"天气预报"（半年到一年）

**Worlds（场景库）。** 今天有平地、坡、台阶、凹凸地面、风、阵风、几个星球。想象它成长为一个**可分享的场景描述语言**：
- 一个场景 = 地形（高度图）+ 地表（摩擦、软硬、沙子）+ 大气（密度、风场随时间变化）+ 重力。
- 社区贡献场景：沙滩坡度、带台阶的走廊、会刮风暴的沙丘。
- **真实风的回放**：导入某个海滩一天的风速记录，看你的设计一整天能走多远——"这只动力兽在荷兰北海 10 月的一个下午能走多少米"。
- **失败也是内容**：Jansen 的 Suicideem 时期整页都在讲它怎么把自己折断。仿真里把"怎么死的"做成一等公民：折断、被沙埋、被浪打、被风吹翻，并给出死因标签。

**价值：** 从"能走"问到"在哪儿、什么时候、走多远、怎么死"。
**缺什么：** 沙地的物理（现在只有"软接触"的粗糙近似，不是沙）；风对机身的作用（现在风只推帆）。**风险：** 沙是整个领域最难的物理之一，别假装解决了它；先接阻力法则（RFT）并明说它的适用范围。

## 3. 中：设计变成"意图"（一到两年）

**Intent compiler（意图编译器）。** 不再拖滑块，而是说一句话：

> "我要一只 40 cm 长、能在每秒 4 米的风里越过 3 cm 台阶、总成本用一卷 PLA 的动力兽。"

系统把它编译成**多目标优化问题**：形态（连杆长度，进一步到拓扑）、帆面积和传动比、腿数相位、材料，目标是越障能力、起步风速、重量、打印时间，输出一条**帕累托前沿**，每个点都是可打印的设计，旁边标着仿真的不确定度。

建立在：遗传算法（已有）、多保真度评估（简化模型粗筛、MuJoCo 复评，已有骨架）、任务队列和扫描（已有）、可打印性检查（已有）。
**缺什么：** 仿真要足够快（需要代理模型，见下一条）；拓扑搜索（现在只演化长度）。
**风险：** 优化会钻仿真的空子（我们已经被钻过三次，见博客）。解决办法是产品化的：每个前沿点自动做"压力测试"（换摩擦建模、换接触刚度、换随机种子，看排名是否还稳）。

**Surrogate（毫秒级代理）。** 用成千上万次仿真训练一个神经代理，设计器里拖滑块时**实时**显示"步幅、起步风速、峰值扭矩"的预测和置信区间，需要精确时再点"高保真验证"。可微仿真（MJX 等）可以直接给出设计对性能的梯度。
**风险：** 代理在训练分布外会一本正经地胡说，必须带不确定度估计，并在界面上显示它"见过多少类似设计"。

## 4. 中：真实世界在回路里（一到两年）

**Sim-to-real loop（仿真与实物闭环）。** 这是整个项目的灵魂，也是目前最缺的：
- **手机即测试台**：只用一段侧视视频（不需要编码器）反推曲柄转速、步幅和脚轨迹，自动校准接触参数。降低"贡献数据"的门槛，让一百个爱好者各测一只。
- **AR 叠加**：手机镜头里，在你的实物上叠一层"设计预测的脚轨迹"，偏差一眼看出（打印误差、间隙、变形）。
- **一份开放数据集**：每条测量带完整出处（设计文件、打印设置、标定、质量报告）。这是风力步行机构领域**几乎不存在**的东西（在我能搜到的范围内：没有找到过含风力和沙地的、经实测验证的完整动力学仿真，不能保证不存在）。仿真器和数据集互相逼对方变诚实。

**Commons（共同体）。** 一个设计注册表：每个设计带它的**实测成绩**（经审核的测量，而不是自称的），像 Jansen 的"Genealogy 家谱页"那样有谱系：谁改自谁，改了什么，成绩怎么变了。社区排行榜按"仿真成绩"和"实测成绩"分开列，两者的差距本身就是一个指标（这个设计的仿真有多可信）。

**缺什么：** 数据，数据，数据。**风险：** 数据质量参差；质量报告和审核流程要做成硬门槛。

## 5. 远：会"思考"的动力兽（三年）

Jansen 在 Cerebrum 时期的做法是：没有电子元件，用**气动的神经**让动物感知世界。他的水感器是一根拖地的软管，一旦吸进水，阻力变大，一个"神经细胞"切换方向；计步器是腿上的小泵，每一步往容器里打一点气，压力降到阈值就掉头。这是**模拟计算**，他用塑料管做了逻辑。

**Pneumatic brains（气动大脑仿真）。** 把这类无电子控制器做成一等对象：
- 气路元件库（瓶子、泵、阀、活塞肌肉、软管水感器），可以拖出一个气动逻辑电路，和机体一起仿真。
- **形态和大脑共同演化**：不只演化腿的长度，也演化气动反射网络，目标是"在涨潮的海滩上活过一个下午"。
- 储能：Vaporum 时期的"风胃"（塑料瓶里储压缩空气）作为可仿真的能量缓冲，回答"无风时能多走几米"。

**Herd & ecology（兽群与生态）。** Tepideem 时期他发现兽群能互相挡风。想象一个**海滩生态仿真**：几十只动物，不同的设计，同一片有风、有潮汐、有沙的海滩，选择压力是"活着、别被冲走"。结果是一棵**演化谱系树**，每个物种都能一键变成可打印的文件。

**缺什么：** 气动元件的可信模型（需要实测）、并行大规模仿真（GPU）。**风险：** 范围爆炸，这是一个独立的研究项目；先做一个能演示"感水转向"的最小例子。

## 6. 科幻：把它送到别的世界（五年以上）

Jansen 在 Bruchum 时期写过，毛毛虫结构也许有一天会被 NASA 带到金星或火星。这不只是俏皮话，它是一个**干净的物理问题**：

> 帆产生的扭矩与空气密度成正比，机体重量与重力成正比。**哪一个世界最适合"靠风走路"的机器？**

这个平台已经能回答一个初级版本（场景库里有月球、火星、泰坦、金星；数值是近似值，来自 NASA 数据表和维基百科）。在我们的小模型上，用 3 m/s 的风、同样的帆，跑两整圈曲柄：地球约 4.2 秒、金星约 3.4 秒（被帆的最高转速限制住）、火星约 29 秒（帆的扭矩小 60 倍，勉强挪动）。这些是**模型在一堆假设下的输出**，不是预言。

继续往下想：
- **行星任务设计器**：选一个目的地（金星近地表、泰坦、火星沙丘、月球无风），系统给出帆面积、传动比、腿数、材料（金星高温下 PLA 当然不行：材料库要带温度范围）的帕累托设计。
- **无电子的探测器**：没有电池、没有芯片、不怕辐射，靠风走路，靠气动逻辑避开障碍和液体——这是 Jansen 的"新的生命形式"这个词的工程版本。
- **自我复制的幻想**：用环境里的材料（泰坦的冰、金星的……）3D 打印下一只。这一层纯属科幻，列在这里是为了说明方向，而不是计划。

**缺什么：** 几乎一切（高温材料、极端大气下的气动、尘埃和静电、真实任务约束）。**风险：** 过度承诺。这一层应该永远被标成"探索性、未验证"。

## 7. 横向：几个不依赖阶段的形态

- **教育与艺术。** 课堂模式（学生拖滑块、猜轨迹、打印、测量、写报告）；VR 里走进一只巨大的动力兽；**放大工具**：给一个设计，输出真正 PVC 电线管版本的切割清单、接头类型和结构校核（大尺寸会失去刚度，Jansen 自己在 Lignatum 时期就为此转向木头）。
- **可微物理的研究平台。** 把仿真器开放成一个"风力步行机构的基准测试"：别人可以提交自己的控制器、拓扑、接触模型，在同一套场景和实测数据上比较。
- **诚实的仪表盘。** 所有结论旁边显示：用了哪个模型层、哪些参数是假设、有没有实测支撑。这是产品的标志性体验，也是对"漂亮但不可信的仿真"的解药。

```
                       │                              │
   Intent ──► Studio ──┼──► Worlds ──► Simulation ────┼──► Foundry（可打印 / 放大版切割清单）
 (意图编译器) (设计工坊) │   (场景库)    (多保真度)      │
                       │                              │
                       └──── Lab（测试台、手机视频、校准）┘   真实数据回灌，让上面每一层更诚实
                                  ▲
                         Brains（气动逻辑，远期）、Ecology（兽群生态，远期）
```

## 9. 如果只能选三件事

按"最能降低不确定性、同时最能让别人参与"排序：

1. **真实测量（Lab）**：不做这个，上面所有层都是空中楼阁。一只打印出来的小动力兽和一条诚实的数据管线。
2. **手机视频测量**：把"贡献数据"的门槛降到一部手机，才有可能得到社区数据集。
3. **意图编译器的最小版本**：在已有的演化、扫描、可打印性检查上，加一个"目标+约束 → 帕累托前沿 + 稳定性压力测试"，让设计者的体验从拖滑块变成提需求。

其余的（兽群生态、气动大脑、行星任务）值得想、值得做小型演示，但不该抢在数据之前。
