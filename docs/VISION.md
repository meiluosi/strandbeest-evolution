# 产品形态与设计愿景（第二版）

> 这是一份**设计与想象力文档**，不是承诺。每个想法都标了：它建立在仓库里已有的什么上、还缺什么、最大的风险是什么。越往后越科幻，也越需要先有真实数据。
> 文献链接来自一次搜索，我**没有逐篇读完**；"SOTA"一词在这里指"搜索里能看到的代表性工作"，不是严格的综述。

## 0. 原则（先立规矩）

1. **诚实本身是功能。** 界面永远显示一个数"来自哪一层、有多不确定、有没有实测"，而不是漂亮的单值。
2. **玻璃盒仿真。** 仿真不是"跑完给你几个数"，而是一个可以走进去检查的过程：每个数字都能拆开看它从哪来。
3. **一套编辑代数（one edit algebra）。** 人、遗传算法、LLM agent、强化学习策略，都通过**同一套类型化的设计操作**改设计。编辑器、优化器、agent、版本历史因此共享一个地基。
4. **生长，而不是调参。** 设计要能在结构上变化（加一个二元组、换一个模块），并随环境长出不同的样子。
5. **AI 原生。** 平台的每个能力都"agent-ready"：有类型化接口、机器可读的 schema、可验证的分数、预算、日志。agent 是一等用户，不是外挂的聊天框。
6. **数据回路。** 真实测量让上面每一层更诚实；没有数据的结论一律标成"模型内"。
7. **可追责。** 谁（人/算法/AI）、在什么时候、为什么改了什么，永远可查；AI 生成的设计打标签；影响现实世界的动作（导出打印、发布）需要人确认。

## 1. 盘点：我们现在在哪（诚实版）

| 能力 | 现状 | 离"愿景"的距离 |
|---|---|---|
| 运动学求解、步态指标、制造规划（分层、间隙、隔套）、MuJoCo 仿真构建 | **已经是通用的**：都基于 `LinkageSpec`，即"二元组链"（每个关节 = 两个圆的交点） | 小 |
| 设计器、滑块、演化基因、3D 装配预览 | **写死了 Jansen**：连杆列表、13 个参数名、`jansenSpec(params)` 散在 `LinkageViewer`、`LengthSliders`、`fitness`、`Viewer3D` | 中：要改成由 spec 驱动 |
| 仿真回放 | **录像**：重放记录下来的姿态，加了足部着地颜色和同步曲线 | 大：见第 2 节 |
| 优化 | 自写的小遗传算法（教学用） | 大：见第 5 节 |
| AI | 无 | 大：见第 4 节 |
| 真实数据 | 工具有，数据没有 | 最大 |

这个盘点里最有用的一条是第一行：**结构化设计离我们比想象的近**，因为求解器、制造、仿真早就不依赖 Jansen 的拓扑了，只有界面和演化还写死着。

## 2. 仿真是一个能"走进去"的过程（玻璃盒）

### 2.1 问题
现在的 3D 回放是**录像**：你看到它动了，但看不到它为什么这么动。我们在这周的工作里已经看到了代价：平地平均扭矩"几乎全是打滑耗散"这个判断，一开始只是我们的推测；我们是靠额外写一个能量账脚本才验证的。验证结果（`packages/sim/scripts/energy_account.py`，小模型电机驱动、跳过起步一圈后平均）：**每圈输入功的 97% 在接触处耗散，3% 在环约束，其余 0.2% 为积分误差**。这个结论本来应该直接显示在界面里，而不是靠一个脚本。

### 2.2 分层的能力（L0 到 L5）

| 层 | 内容 | 状态 |
|---|---|---|
| L0 录像 | 回放记录的姿态，足着地变色，同步曲线 | **已有** |
| L1 叠加 | 接触力矢量和接触点、关节反力、扭矩流向、打滑指示（脚的切向速度）、质心轨迹与支撑多边形、**足迹图**（每条腿的着地/抬脚时序）、相位环、**能量流桑基图**（风/电机 → 曲柄 → 势能/动能 → 接触耗散/环约束耗散） | 数据可得（MuJoCo 的约束力和速度），要记录和画 |
| L2 事件与因果 | 自动检测并标注：落脚、抬脚、打滑、被地形挡住、环约束张开、起步/停转、阵风；时间线上点事件就跳转；**"它为什么停了？"** 的自动诊断（规则找出证据，AI 把证据讲成人话） | 全部要做 |
| L3 交互 | 实时流式仿真（后端 WebSocket 步进，或浏览器里的 MuJoCo WASM）；拖拽推它一下；运行中改风、摩擦、坡度；**暂停、检查、改参数、从这一帧继续（分叉）**；保存状态检查点做时间旅行；A/B 并排同步回放并高亮差异 | 要做；WASM 的可行性要先实测 |
| L4 多尺度 | 整机 ↔ 单腿 ↔ 单个销孔的受力和应力（梁或有限元），Suicideem 时期的"折断自己的脊梁"应当能被预警 | 远 |
| L5 沉浸 | VR 里走进去；AR 把预测的脚轨迹叠在你的实物上 | 远 |

### 2.3 技术方案要点
- **录得更多**：每帧加每个脚接触的法向/切向力、关节反力、各能量项；独立的**事件日志**（带时间、类型、证据）。数据量预算：现在 6 腿小模型 30 Hz × 2 秒约 1 MB 的 JSON，再加力和能量大概翻倍，可接受；12 腿大模型要做抽稀和二进制传输。
- **API**：`GET /runs/{id}/replay?layers=forces,events,energy`；`WS /sessions` 做实时会话（`step`、`pause`、`set(param)`、`fork`）。
- **前端**：一个 Inspector 面板（选中一只脚或一个关节，显示它的力、功率、历史）；时间线轨道（事件、足迹图）；叠加层开关。
- **对科学诚实的作用**：玻璃盒让不确定性可见。比如平均扭矩依赖摩擦的数值处理（相差最多 2.4 倍），能量桑基图会**直接显示"这个数就是打滑耗散，所以它对摩擦建模敏感"**，而不是让用户读文档。

### 2.4 风险
- 实时流式仿真对后端的算力和延迟要求高；先做"跑完后可检查"（L1、L2），再做实时（L3）。
- 叠加层太多会变成噪音；默认只开两三个，其余按需。

## 3. 设计是结构，不是参数

### 3.1 设计 IR（中间表示）
把设计从"13 个长度"升级为一张**图**：

- **节点**：`Ground`、`Crank`、`Link`、`Joint`（二元组关节）、`Foot`、`Body`、`Sail`、`Rotor`、`Spring`；远期：`Bottle`、`Pump`、`Valve`、`Piston-Muscle`、`Water-Feeler`、`Pedometer`（Jansen 的气动元件）。
- **属性**：长度、质量、材料、制造参数、颜色、备注。
- **约束**：装配（全周期可装配、分支一致）、可打印性、无碰撞、对称、自由度 = 1。
- **模块**：`Leg` 是可复用模块；`array(Leg, n, phases)` 生成多腿；机身、帆、曲轴也是模块。

现有的 `LinkageSpec` 是这个 IR 的**子集**：每个 `JointDef` = 两个圆的交点 = 一个 RRR **二元组（Assur dyad）**。平面单自由度机构有一大类可以由二元组链构造，所以这个子集不小；但**不是全部**（含滑块的机构、需要同时求解多个环的结构，不是简单的二元组链）。把这条边界明说出来，比假装通用要好。

### 3.2 编辑代数
所有改动都是类型化操作，每个操作有**前置条件检查、可逆、产生 diff、写入日志（谁/何时/为什么）**：

```
add_dyad(centers, radii, side)     remove_joint(id)       set_param(name, value)
scale(group, factor)               mirror(group)          array_legs(n, phases)
split_link(id, at)                 insert_module(kind, at)  set_material(group, material)
attach(sail | spring | sensor, at) rename / tag / note
```

为什么这是整套设计的支点：
- **编辑器就是操作的可视化**：拖一个点 = `set_param`，点"加二元组" = `add_dyad`。
- **遗传算法的变异和交叉 = 操作序列**：拓扑变异（加/删二元组）不再是特殊代码，有效性由求解器兜底。
- **agent 的工具集 = 操作集**，强化学习策略的动作空间也是操作集。
- **版本控制和谱系是免费的**：操作日志就是补丁序列，谱系树（Jansen 网站上就有一页 Genealogy）就是日志的分叉图。
- **可复现**：同一份初始设计加同一串操作，得到同一个结果。

### 3.3 编辑器（给人用，也给 agent 用）
三个联动的视图：
1. **机构草图（2D）**：直接拖点、加二元组；实时显示**自由度、装配范围、奇异位形警告**和脚轨迹；红色 = 装不起来 / 会碰撞 / 不可打印。
2. **结构树**：腿、曲轴、机身、帆；复用和阵列。
3. **3D / 制造**：零件、叠放层、装配；就是现在的制造页，但和前两个视图联动。

外加：**命令面板**（人和 agent 共用同一套命令）、**历史/分支/对比面板**（谱系树）、**试验台侧栏**（随手选个场景跑一下看效果）。

### 3.4 "生长"：三种含义
1. **演化式**：种群 + 环境选择（质量多样性，见第 5 节）。
2. **发育式**：设计由**生长程序**生成（L 系统、图文法、CPPN），环境参数是输入。设计变成函数：`design = f(environment)`，风大则帆小腿矮，沙软则脚大。一份"设计家族"文件含可调参数和适应规则，在不同场景实例化出不同的个体（"物种"）。
3. **使用中适应**：可调机构（调帆、调腿长、锚）和气动反射（Jansen 的 Cerebrum 时期：软管水感器和计步器，用气路做逻辑）。这是**形态计算**：用机构本身完成"控制"。

### 3.5 范围与风险
- 拓扑编辑让搜索空间爆炸；先做**有效性守门**（全周期可装配、分支翻转、自由度、可打印、碰撞），无效设计在进入仿真之前就被拒绝。
- 渐进路线：(a) 让查看器/滑块/基因/3D 由 spec 驱动（去掉写死）；(b) 加 `add_dyad`；(c) 拓扑演化；(d) 模块与气动元件。

## 4. AI 原生

### 4.1 三种角色，外加"在回路里的模型"
- **协作者**：对话式地改设计、解释结果、回答"为什么"。
- **操作员（agent）**：通过工具自己跑实验、扫描、优化、整理记录。
- **分析师**：读回放和数据，写出带出处的报告。
- **回路里的模型**：代理模型、神经校准、生成模型、策略（第 5 节）。

### 4.2 Agent-ready 的五个条件
平台的每个能力都要满足：**① 类型化接口，② 机器可读的 schema，③ 可验证的数值分数，④ 预算（时间/算力/成本），⑤ 日志**。我们的 `schemas/`、任务队列、运行记录已经满足一大半；缺的是把它们包成 agent 能发现和调用的协议。

### 4.3 工具面（MCP 服务器）
以 Model Context Protocol（MCP）这类标准协议暴露（搜索结果称它已成为 LLM agent 接入外部工具的主流标准）：

| 工具族 | 例子 |
|---|---|
| `design.*` | 编辑代数的全部操作、`validate`、`diff`、`history` |
| `simulate.*` | `run`、`sweep`、`replay.query`（只取需要的层和时间段）、`inspect.event`、`render.frame`（给多模态模型看图） |
| `fab.*` | `export`、`checks`、`bom` |
| `lab.*` | `import`、`compare`、`calibrate`、`quality` |
| `notes.*` | 读写实验记录（`EXPERIMENTS.md`），强制带数字和出处 |

每个工具带权限等级：**只读 / 可写设计 / 可跑仿真（耗预算）/ 可导出文件（需人确认）**。不允许 agent 自己发布或打印。

### 4.4 闭环：提出 → 编辑 → 仿真 → 批评 → 修订
搜索里已经有这类思路的代表性工作：把 CAD 生成、CAE 求解、结果解析、几何修订做成一个交互式强化学习环境（[COSMO-Agent](https://arxiv.org/html/2605.20190)、[ToolCAD](https://arxiv.org/html/2604.07960)、[CADDesigner](https://arxiv.org/pdf/2508.01031)），以及 [LLM 赋能的下一代 CAE](https://arxiv.org/html/2509.11447v1) 的综述。我们的区别是：**批评来自多个互相独立的来源**——指标、压力测试（换摩擦建模、换接触刚度、换随机种子，排名是否稳定）、视觉（渲染帧给多模态模型看"这条腿摆动时拖地了吗"）、物理一致性检查。

### 4.5 几个具体的 agent
- **实验员**：设计实验（主动学习、最优实验设计：下一步该测哪个条件信息量最大）、跑扫描、总结、把结果和否定性结果写进实验记录。
- **仿真器的怀疑者（自检 agent）**：专门去找仿真器的 bug。我们这周的 bug 就是靠一个朴素的问题发现的："为什么脚一直都在着地？" 让 agent 系统地做这件事：对不变量做**模糊测试**（能量守恒、镜像对称、步幅对比运动学、接触数合理性、质量缩放不变性、改单位不变性）。
- **意图编译器**：自然语言 → 结构化目标和约束 → 优化问题 → 候选设计 → 压力测试 → 解释。**LLM 只做翻译和解释，数值部分交给优化器和仿真器**，不让 LLM 猜物理。
- **数据员**：从手机视频/照片抽取测量（视觉模型加 ArUco），质量审核，异常检测。
- **知识层**：把 Jansen 官网页面、论文、我们的实验记录做成可检索知识，**回答必须引用来源，否则标"假设/未验证"**。

### 4.6 把平台变成训练和评测 agent 的沙盒
"设计 → 仿真 → 数值成绩"是一个**带可验证奖励**的环境。这既是评测 agent 的好基准（**设计基准**：给定意图和预算，比较 agent 与遗传算法、贝叶斯优化基线在盲测场景下的成绩），也是后训练 agent 的好环境（RLVR 风格）。

### 4.7 护栏
- 所有 agent 改动可审计、可回滚；AI 生成的设计打标签。
- **防钻空子**：我们已经被遗传算法钻过三次空子（脚穿过机身、只滑不抬、"平"随抬腿变松）。agent 比遗传算法更会钻；所以评分永远含**压力测试**，且评估场景对 agent 保密（避免评估泄漏）。
- 预算和成本上限；影响现实世界的动作需要人确认。

### 4.8 风险
物理幻觉（LLM 编造数字）、对仿真过拟合、评估泄漏、成本失控。对策都写在上面了，但值得再强调一遍：**AI 在这个项目里的价值是"让人更快地看见真相"，不是"替人下结论"**。

## 5. 算法地图

筛选原则：只收**和这个问题直接相关**的方法；每条标出"适合什么、不适合什么、前置条件"。"现有"指仓库里已经有的东西。

### A. 连续参数优化
| 方法 | 适合 | 备注 |
|---|---|---|
| **CMA-ES** | 10–50 维连续参数、噪声不大 | 稳健、几乎免调参；替换自写 GA 的第一选择 |
| **贝叶斯优化**（GP、TuRBO） | 评估很贵（一次 MuJoCo 几十秒）、样本少 | 用不确定度决定下一个试哪 |
| **多保真度 BO / Hyperband / BOHB** | 我们**天然有两个保真度**（简化模型便宜、MuJoCo 贵） | 现有骨架已经是"简化筛选、MuJoCo 复评" |
| **梯度法 / 可微仿真** | 简化运动学模型（圆交点可解析求导，可用 JAX 自动微分）；MJX/Warp 对接触不光滑，需要平滑化 | 梯度能直接给出"设计对性能的灵敏度" |

### B. 多目标
**NSGA-II/III、MOEA/D**；BO 侧有 ParEGO、qNEHVI；加上**偏好学习**（人在回路里从帕累托前沿上挑，系统学会他的取舍）。对应"意图编译器"的输出：一条前沿，而不是单个解。

### C. 多样性与开放式演化
**MAP-Elites / 质量多样性（QD）**：存档按特征（腿数、步幅、起步风速、重量……）分格，每格保留最好的——**谱系树的数学版本**。新奇性搜索；**POET / 开放式协同演化**（环境和设计一起演化）。
**必须记住的警告**：搜索里有一串工作指出，**脑体共演化经常选不出有形态潜力的身体**，控制器和身体互相拖累（[演化式脑体共优化持续失败](https://arxiv.org/pdf/2508.17464)；[控制器蒸馏缓解](https://arxiv.org/abs/2504.06523)；[具身共设计的分类与挑战](https://arxiv.org/pdf/2512.04770)）。对我们：未来设计气动"大脑"和身体一起演化时，要从一开始就把这一点当作已知难题，而不是默认能行。

### D. 机构综合与拓扑
- **经典**：枚举（Assur 群、图同构）加优化。
- **数据驱动**（搜索里的代表性工作）：[LINKS：一亿个平面连杆的数据集](https://arxiv.org/pdf/2208.14567)；[LInK：对比学习联合表示设计与性能，在千万级机构上检索](https://arxiv.org/html/2405.20592v1)；[四连杆的深度生成模型（cGAN、VAE）](https://arxiv.org/html/2402.14882v1)；[MechaFormer：把机构综合当序列学习](https://arxiv.org/pdf/2508.09005)；还有把强化学习用于单条目标曲线综合的工作（我没有逐篇核对）。
- **对我们的启示**：这些工作的目标大多是**跟踪一条目标路径**；我们的目标是**步态质量 + 动力学 + 可制造**。可用思路是**"先检索、再微调"**：用数据集里的相似机构做起点，换成我们自己的评价函数继续优化。注意：这些数据集多是四连杆或通用平面连杆，不含"可打印性、层分配、帆"这些约束。
- 我们已经有一篇相关的多目标工作作为参照：[Jansen 连杆的耐久性感知多目标优化](https://arxiv.org/pdf/2606.22129)（步态质量对关节磨损）。

### E. 强化学习：用在哪里（诚实评估）
**不适合的地方**：Jansen 腿本身是**被动机构**，没有控制器可学。拿 RL 去优化"曲柄转一圈脚怎么走"没有意义。

**适合的地方**：
1. **设计者策略**：把编辑代数里的操作当动作，逐步编辑设计，回报是仿真成绩。这正是搜到的 CAD-CAE 强化学习环境的思路。它尤其适合拓扑编辑的**组合爆炸**和**可行性约束**（策略学会不产生无效设计）。
2. **受控变体**：有驱动的版本（电机变速、调帆、调腿长）的控制策略，例如跟着阵风调帆、遇到障碍加力。
3. **气动反射控制器**的演化（神经演化、进化策略，必要时 RL）。
4. **稳健性**：在风、地形、摩擦的**域随机化**下训练策略或评估设计。
5. **LLM agent 的后训练**：把仿真成绩当可验证奖励。
**成本和风险**：样本效率低；MuJoCo 单线程只有 kHz 量级，需要 MJX/GPU 或大规模并行；奖励钻空子。

### F. 代理模型与神经算子
高斯过程、神经网络集成、对机构图用图神经网络；**主动学习**决定下一批仿真；不确定度用深度集成或**共形预测**。目标：设计器里拖滑块时**毫秒级**预测步幅、起步风速、峰值扭矩，并显示置信区间和"它见过多少类似设计"。

### G. 校准与推断（这是最贴近现在瓶颈的一组）
- **贝叶斯校准**：MCMC/HMC、ABC、**基于仿真的推断（SBI，神经后验估计）**、集合卡尔曼反演——给出参数的**后验分布**，而不是点估计。
- **可辨识性分析**（Fisher 信息、剖面似然）：我们已经看到接触刚度、摩擦、腿质量之间可能互相掩盖；应当先问"这批数据能不能把它们分开"，再去拟合。
- **最优实验设计**：下一个该测哪个条件（转速、表面、风速）信息量最大。
- **多保真度校准**：简化模型当先验均值，MuJoCo 修正（残差高斯过程）。

### H. 稳健与不确定性
域随机化、**CVaR 优化**（优化最坏的 10% 情况）、**对抗场景搜索**（用进化或优化去找让设计失败的最坏风和地形）、可靠性分析（蒙特卡罗）。这和第 4.7 节的"压力测试"是同一件事的两面。

### I. 结构与材料
**拓扑优化（SIMP）**给杆件减重；梁/壳有限元看销孔应力；疲劳（Suicideem 的教训）；FDM 打印的各向异性（层间强度）。

### J. 约束与可行性
可行性分类器、安全贝叶斯优化、约束 CMA-ES；**层分配现在用贪心着色，可以换成整数线性规划求最小层数**（现成的最小改进，而且能证明最优）。

### K. 自动化科学
- **符号回归 / SINDy**：从仿真和实测里发现经验公式（"起步风速 = f(帆, 传动比, 质量)"、扭矩的缩放律）。
- **程序搜索 / LLM 引导的演化**（FunSearch、AlphaEvolve 一类）：搜索的对象不是参数，而是**生成设计的程序**或**适应度函数本身**。
- **因果推断**（和你的背景直接相关）：我们遇到过一个现象：腿越重平均扭矩越大，但总质量固定，原因没弄明白。这正是"相关还是因果"的问题。仿真里可以做**干预实验**（`do(腿质量)`，其它不变），真实世界只能受限地做。把"为什么"变成可以系统回答的问题。

### 优先级建议（不追求全）
1. **用成熟库替换自写 GA**：pymoo、`cma`、BoTorch/Ax、pyribs（QD）、`sbi`。工程原则：别重造优化器，精力放在**问题的表述、评估器、防钻空子**上。
2. **多保真度筛选 + 质量多样性存档**（直接对应"谱系"）。
3. **贝叶斯校准 + 可辨识性分析**（直接对应当前最大的瓶颈：怎么用很少的真实数据给出诚实的参数）。
4. **BO 做昂贵仿真的小样本优化**。
5. 其余（RL 设计者、生成模型、代理模型、拓扑优化）先做小型演示，别抢在数据和编辑器之前。

## 6. 产品形态（整合）

```
                    ┌─────────── Agents（MCP 工具面 + 评测基准 + 护栏）───────────┐
                    │                                                              │
 Intent ──► Editor ─┼─► Worlds ──► Simulation（玻璃盒，多保真度）──► Foundry        │
(意图编译) (结构化设计  │   (场景库)     L0 录像 … L3 实时/分叉     (可打印 / 放大版切割清单)│
           + 编辑代数) │                                                              │
                    └──────── Commons（设计注册表、谱系、带实测成绩的排行）─────────┘
                                         ▲
                       Lab（测试台、手机视频、校准、可辨识性）──真实数据回灌
```

- **Studio / Editor**：第 3 节。
- **Worlds**：场景库（地形、风、天气回放、行星）；沙地要谨慎，先接阻力法则并明说适用范围。
- **Foundry**：可打印导出和**放大工具**（给一个设计，输出 PVC 电线管版的切割清单、接头、结构校核；Jansen 自己在 Lignatum 时期就为大尺寸刚度而改用木头）。
- **Brains & Ecology（远期）**：气动逻辑元件库、形态与大脑共演化、兽群与海滩生态（Jansen 的 Tepideem 时期发现兽群能互相挡风）。
- **Planets（探索性）**：帆扭矩正比于空气密度，重量正比于重力，哪个世界最适合"靠风走路"？场景库里已有月球、火星、泰坦、金星的近似数值。在小模型上，3 m/s 的风，同样的帆，两整圈曲柄：地球约 4.2 秒、金星约 3.4 秒（被帆的最高转速限制）、火星约 29 秒；**这些是模型输出，不是预言**。Jansen 在 Bruchum 页面里半开玩笑地说 NASA 也许会把毛毛虫带去金星或火星，这是个干净的物理问题，应当永远标成"探索性、未验证"。
