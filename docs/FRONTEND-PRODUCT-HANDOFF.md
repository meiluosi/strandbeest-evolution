## 1. 给接手开发者的结论

这不是一次“换皮”，也不是用概念 Demo 替换现有应用。目标是保留现有几何、编辑历史、演化、仿真与回放能力，将其重组为一个连贯、可理解、可验收的产品工作流：

**设计机构 → 演化候选 → 应用为设计分支 → 场景仿真 → 回放与对比。**

已确认的产品气质是：

**精密机械图纸 + 现代实验仪器 + 少量海滩生命感。**

不要做成通用管理后台、卡片堆砌的 Dashboard、赛博风大屏或营销落地页。视觉服务于机构观察、参数调整和证据阅读，而不是遮盖这些信息。

实施时必须遵守以下优先级：

1. 仓库规则、Design／Scenario／Run 等数据契约和真实计算结果是最高约束。
2. 本文记录已确认的产品方向、信息架构、状态边界和实施顺序。
3. 概念 Demo 只作为布局、视觉、文案层级和交互手感参照，不是新的数据模型或技术架构。
4. 如果 Demo 与真实能力冲突，保留真实能力并调整界面；不要伪造数据去迎合 Demo。

## 2. 概念 Demo：位置、运行与证据边界

### 2.1 运行

从仓库根目录进入独立 Demo：

```bash
cd apps/web-demo/product-demo
npm install
npm run dev -- --host 127.0.0.1 --port 7100
```

构建与浏览器测试：

```bash
npm run build
npm test
```

也可以一次执行：

```bash
npm run build && npm test
```

说明：

- Demo 使用独立的 npm 脚本，不依赖仓库后端。
- `npm test` 使用 Playwright 和本机 Edge（`channel: "msedge"`），通过 Vite Preview 访问 `127.0.0.1:7100`；先构建再测试。
- 正式 monorepo 仍遵循根 `AGENTS.md`，使用 pnpm 和 Node >= 22。

## 3. 产品原则

### 3.1 一份设计，贯穿工作流

- 当前 Design 是设计、演化和仿真共同的上下文。
- 页面顶部持续显示当前设计名称与状态；切换工作区不应让用户怀疑正在操作哪个对象。
- 演化结果“应用”后必须形成可追踪的设计分支与编辑操作，不能只替换画面上的连杆。
- 仿真启动时固定使用该次运行的 Design 快照；后续编辑不能悄悄改变已完成运行的含义。

### 3.2 画布优先，控制随之而来

- 机构、轨迹和 3D 回放是主角，控制面板是解释和操作它们的工具。
- 主画布、关键指标和主操作应在首屏形成清晰视觉路径。
- 高级 schema、资产、历史、风驱动、扫描等能力可以进入分区或渐进披露，但不得直接删除。
- 避免所有信息都变成等权卡片；用位置、尺寸、间距和字体层级表达主次。

### 3.3 状态可见，因果可解释

- 拖动与滑杆输入是预览，提交后才进入 Operation 历史；两种状态要有清楚反馈。
- 运行中、已停止、失败、空结果、不可装配、后端离线等状态都要有明确界面，不用永远正确的动画掩盖。
- 每个异步操作有进行中与结束反馈；重复提交和过期响应不能覆盖更新的状态。
- 撤销、重做、导出等全局入口只在有真实上下文时启用，并说明作用对象。

### 3.4 证据分级，不用视觉拔高结论

- 运动学、浏览器物理预览、后端物理运行、记录回放必须可区分。
- 保留并强化 `EvidenceBadge`、假设、运行 ID、场景、单位和限制说明。
- 演示数值不得进入正式页面；没有数据的指标显示空态，而不是 0 或随机数。
- 本轮前端工作不能宣称解决既有物理验证、H2／H5 或性能任务。

## 4. 信息架构与页面规范

### 4.1 App Shell

概念 Demo 的三项主导航是“设计 / 演化 / 仿真”。正式实现应建立相同的主工作流，同时保留现有功能：

- 顶栏：产品标识、当前设计、保存／同步状态、撤销重做、上下文导出、主题、语言。
- 侧栏：设计、演化、仿真为一级工作区。
- 现有“制造 / 数字海滩 / 实验室”不能因这次重构消失；可放入二级导航或“更多”分组，保持可发现与可访问。
- 静态版与后端版继续根据 `STATIC` 和在线状态显示真实可用能力。
- 保留现有 `?tab=` 深链行为；若改导航实现，先做兼容，不要求为此引入路由器。
- `Cmd/Ctrl+K` 命令面板和 `Cmd/Ctrl+Z` 编辑历史行为不能因 Shell 改造失效。

移动端可使用紧凑顶栏和底部／抽屉导航，但主导航、当前设计和主操作不能只能靠 hover 发现。

### 4.2 设计工作台

目标：让用户在一个视野内理解“当前机构是什么、正在改什么、结果怎样”。

- 中央：大比例机构画布，支持现有拖动、播放、足端轨迹与视图图层。
- 右侧或邻近检查器：常用杆长与参数，分组呈现；当前编辑值、单位和有效范围明确。
- 画布下方：少量核心步态指标和状态；不可装配时解释问题，不保留误导性的旧指标。
- 次级区域：文件、SchemaForm、资产、历史、风驱动等按任务分组，不与主画布争夺首屏注意力。
- 撤销／重做与拖动／滑杆共用现有 Operation 历史，不为新控件建立另一套编辑路径。
- 设计页的导出、分享、保存与加载沿用现有实现，并按静态／后端环境呈现。

### 4.3 演化工作台

目标：把演化从设计页底部的高级折叠区提升为可理解的工作流程，但不虚构算法能力。

- 配置区：当前真实支持的目标、种子、代数、种群；值含义和运行成本可理解。
- 运行区：开始、停止、当前代数、最佳／平均适应度、错误和完成状态，全部来自 Worker 消息。
- 结果区：适应度曲线、初始与当前最佳足端轨迹、应用到设计。
- 图鉴区：复用真实 MAP-Elites 数据与加载行为，与本次 GA 运行清楚分区。
- 在真实多候选接口出现之前，界面只展示当前最佳个体，不沿用 Demo 的多候选卡片和假排名。
- “应用候选”必须沿用 `applyEvolved()` 的分支和算法 Operation 语义。

### 4.4 仿真与回放工作台

目标：先选择实验，再观察证据；播放、图层、事件、图表和对比围绕同一次运行协作。

- 场景选择来自 `contracts/scenes.json`，说明场景差异和当前驱动方式。
- 主区域复用 `ReplayViewport`，保留轨道相机、iso／side／top、跟随和已有视觉图层。
- 播放条、速度、事件时间线、足端图、能量与曲线共享现有统一时间。
- A/B 使用同一时钟、可识别的标签和真实指标差值；移动端上下排列，不压缩成不可读的双列。
- 浏览器 WASM、后端运行、静态烘焙 Replay 的来源与保真度持续可见。
- 扫描、运行历史和高级 solver 设置可以渐进披露，不能为了接近 Demo 而删除。
- 没有 Replay、图层数据或事件时展示具体空态；不得播放示意动画冒充新运行。

## 5. 视觉、动效与响应式契约

### 5.1 视觉 Token

以 `apps/web-demo/product-demo/src/styles.css` 为参照，将语义映射到正式应用的全局样式，不要逐页复制颜色字面量。

| 语义 | Demo Token | 用法 |
| --- | --- | --- |
| 页面与表面 | `--bg`、`--surface`、`--surface-raised`、`--surface-muted` | 沙色中性底，暗色使用同一语义反转 |
| 文字 | `--text`、`--text-soft`、`--text-muted` | 标题、正文、辅助信息三级层级 |
| 品牌与主操作 | `--accent`、`--accent-strong`、`--accent-soft` | 铜橙色，只强调当前选择和关键动作 |
| 成功与有效 | `--success`、`--success-soft` | 有效、完成、稳定；不代替文字 |
| 对比与次级数据 | `--blue-0` | 曲线、对比或次级观测，不与主操作争抢 |
| 错误 | `--danger-0` | 失败、无效与危险状态 |
| 边界 | `--line`、`--line-strong` | 图纸式细分隔，避免厚重卡片边框 |
| 画布 | `--canvas-bg`、`--grid-line`、`--stage-bg` | 保持机构与轨迹的对比度 |
| 圆角与阴影 | `--radius-sm/md/lg`、`--shadow-sm/lg` | 轻量仪器感，避免悬浮营销卡片 |

字体参照：

- UI：Manrope + 中文系统字体回退。
- 数字、参数、运行 ID：IBM Plex Mono。
- 正式应用优先复用现有依赖与本地资源；新增图标或字体依赖必须说明理由，不为了照搬 Demo 引入平行工具链。
- 不依赖运行时外部字体或图片请求。

### 5.2 动效

- 控件反馈约 120–180ms，面板与内容切换约 180–240ms；以 Demo 的实际手感为参照，不堆砌缓动。
- 动效只解释状态变化：选择、展开、应用候选、运行进度、时间定位。
- 不使用循环漂浮、无意义粒子、大幅视差或干扰阅读的入场编排。
- 播放动画由真实机构相位或 Replay 时间驱动；不能用 CSS 动画伪装物理运动。
- `prefers-reduced-motion: reduce` 下关闭非必要过渡与自动视觉运动，保留用户主动播放和清晰状态变化。

### 5.3 响应式与可访问性

- 1440：完整 Shell、主画布与检查器并排。
- 1024：收紧间距和次要信息，不缩小到难以阅读。
- 768：工作区改为单列或可切换面板，保持主任务连续。
- 375：单列、可横向容纳必要数据、主操作可达，无页面级横向溢出。
- 键盘可完成导航、参数编辑、运行控制和时间定位；拖动不能是唯一编辑方式。
- 所有图标按钮有可访问名称，焦点清晰，表单标签与控件关联。
- 触屏主要点击目标建议至少 44×44px；桌面紧凑布局也不能牺牲可用性。
- 状态不只靠颜色表达；图表有图例或文字摘要。
- 中英文同样检查文字截断、溢出和布局跳变。

## 7. 状态主权：不要在重构中复制状态

| 状态 | 当前事实来源／所有者 | 前端重构约束 |
| --- | --- | --- |
| 当前 Design | `editor.svelte.ts` 的 `History`；只读视图经 `editor.design`、`currentDesign()`、`view` | 组件不得直接改 Design；所有提交走 Operation API |
| 拖动／滑杆预览 | `editor.preview`，由 `previewDesign()` 派生显示 | 预览不是已提交设计；取消和提交语义要保留 |
| 撤销、重做、编辑日志 | `History` 与 `editor.steps/canUndo/canRedo` | Shell 按钮只是命令入口，不维护第二份历史 |
| 本地设计目录与分支 | `editor.catalog`、`branchDesign()` 等 | 不用 Demo 的候选数组替代设计目录或谱系 |
| 当前工作区 | `App.svelte` 的 `tab` 与 `?tab=` | 可重构 Shell，但保持深链与现有页面可达 |
| 后端地址与在线状态 | `store.api`、`App.svelte` 的 health 检查 | 不用“保存成功”代替在线或同步状态 |
| 演化配置与运行 | `Evolver.svelte` 的局部状态、Worker、`GAState[]` | 进度和曲线只由真实消息驱动；停止不是完成 |
| 场景选择 | `ScenePlayer.svelte` 的 `key`，场景定义来自 `contracts/scenes.json` | 场景变更不自动伪造运行结果 |
| 当前／上一次 Replay | `ScenePlayer.svelte` 的 `replay`、`previous` | A/B 标签必须指向真实 Replay 与来源 |
| 回放时间 | `ScenePlayer.svelte` 的单一 `time` | 视口、时间线和图表读取同一时间；不能在子组件各建时钟 |
| 播放、速度、相机、图层 | `ScenePlayer.svelte`；相机预设局部位于 `ReplayViewport` | 只有跨组件共享时才提升状态，不建立无关全局 Store |
| 仿真 Job、扫描与历史 | `SimTab.svelte` 的 `job/busy/current/history` 等 | 保留取消、错误、进度与空态；不要与 GA Worker 状态混为一谈 |
| 语言 | `i18n/index.svelte.ts` | 继续使用响应式 `t()`，同步维护中英文目录 |
| 主题与面板偏好 | Demo 中的 UI 偏好；正式应用可新增独立偏好状态 | 不写入 Design Operation 历史；主题需与 3D 视口一致 |

原则：先在拥有交互的组件内保持局部状态，只有跨工作区或跨组件确实需要时才提升。不要新建一个包罗万象的 `productStore`。

## 8. 分阶段实施与验收

每个阶段只做一个可审查的切片。不要同时重写三页，也不要在视觉改造中顺手重写物理内核。

### P0-A：设计 Token 与 App Shell

范围：

- 建立语义 Token、字体层级、主题和基础控件样式。
- 改造 `App.svelte` 的 Shell 与导航，接入真实当前设计、历史和语言状态。
- 保留制造、数字海滩、实验室及所有现有环境提示。

验收：

- 三项主工作流可达，现有二级功能无丢失，`?tab=` 与快捷键可用。
- 撤销／重做状态与 `editor.canUndo/canRedo` 一致；非设计上下文不会误改设计。
- 静态版、后端离线、后端在线提示保持真实。
- 中英文、明暗主题、键盘焦点、减少动态效果和 375–1440 布局通过检查。

### P0-B：设计工作台

范围：

- 重排 `DesignTab`、`LinkageViewer`、`LengthSliders` 和次级面板，形成画布优先布局。
- 接入真实预览、提交、指标、保存、分享和导出状态。
- 补齐空态、错误态和移动端布局。

验收：

- 滑杆与关节拖动都遵循“预览 → 单次 Operation 提交”，撤销／重做结果正确。
- 指标来自真实几何，单位明确；不可装配时不展示陈旧的正常指标。
- 应用预设、打开设计、保存／分享／导出仍走现有路径，无平行 Design 数据。
- 设计核心流程在中英文、明暗主题和 375／768／1024／1440 下可完成。
- 浏览器控制台无新增错误，网络无新增 404。

### P1：演化工作台

范围：

- 将真实 `Evolver` 提升为主工作区，沿用 `ga.worker` 和 `GAState`。
- 重排配置、运行、曲线、轨迹和图鉴；实现真实空态、停止、失败与完成。
- 沿用 `applyEvolved()` 的设计分支与算法 Operation。

验收：

- 使用固定 seed 可以重复启动真实 GA；代数、最佳／平均适应度与 Worker 消息一致。
- 停止后状态为已停止而非成功完成；Worker 错误可见且界面可恢复。
- 初始／最佳轨迹来自 `trace()`，最佳个体应用后产生正确子设计与可撤销历史。
- 不显示虚构 top-N、约束结果或 MAP-Elites 运行状态。
- 导航离开与返回、重复启动、Worker 清理不产生重复运行或陈旧响应。

### P2：仿真与回放工作台

范围：

- 重排 `SimTab` 与 `ScenePlayer`，统一场景、运行、视口、时间线、图层和对比的视觉语言。
- 保留静态烘焙、浏览器 WASM、后端运行、扫描、历史、录制与证据。
- 只做必要的 HUD／样式和状态呈现调整，不重写 Replay 渲染器。

验收：

- 场景来自契约；启动运行后只展示该次真实结果，加载期间不混用旧运行标签。
- 播放、seek、事件定位、足端和图表共享时间；A/B 同步且标签、单位、Δ 正确。
- 图层只在数据存在时可用；无 Replay、取消、失败、 stalled 和后台标签页警告有明确状态。
- 静态／浏览器／后端来源和 EvidenceBadge 可识别，限制说明可发现。
- 明暗主题下 3D 视口和页面一致，375 宽度下 A/B 改为可读布局。

## 10. 明确禁止

- 用 `product-demo` 的 Vanilla DOM 实现替换正式 Svelte 架构。
- 复制 Demo 的演示数组、定时器进度或随机指标到正式页面。
- 新建平行 Design、Scenario、Run、GA 或 Replay 数据模型。
- 直接修改 Design 对象，绕过 Operation log、guard、撤销／分支语义。
- 为视觉统一而重写几何、物理、Worker 或 Three.js 内核。
- 把“本地日志已持久化”“后端已保存”“运行已完成”混为一种状态。
- 为接近 Demo 删除制造、数字海滩、实验室、扫描、历史、证据或高级设置。
- 在静态版或无数据时提供看似成功但没有真实结果的保存、导出、运行操作。
- 未经用户确认发布任何站点、包或导出内容。

### 11.3 边界与下一步

P0 没有重写演化算法、仿真状态或 Replay 渲染器。演化目前由一级导航打开现有 `Evolver` 区域；仿真仍沿用现有页面组合。P1／P2 的产品级布局尚未实施，不能据 P0 的通过结果宣称全部前端重构完成。

本轮浏览器证据限于固定 Linux Chromium，不包括 Firefox／WebKit；没有运行完整 Python／Rust 测试，也没有改变或重新验收物理模型、H2／H5 和性能任务。

下一切片只推进 **P1 演化工作台**：

1. 先梳理 `Evolver.svelte` 的 Worker 生命周期、固定 seed、停止／失败／完成和离开工作区时的清理行为，补针对性回归。
2. 再重排真实配置、进度、适应度曲线、初始／最佳轨迹和 MAP-Elites 分区；没有真实接口前不加入 top-N 候选或约束结果。
3. 验证 `applyEvolved()` 仍创建设计子分支和算法 Operation，且可撤销；导航往返、重复启动和陈旧响应不得制造重复运行。
4. P1 独立通过功能、浏览器和中英文响应式验收后，再进入 P2 仿真与回放，不同时展开两个切片。
