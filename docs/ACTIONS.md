# 行动计划：任务卡

> 用法：**点名派活**，例如"做 E1-01"或"把 E3 整个做完"。每张卡有目标、验收（可验证的门槛）、依赖、规模和"需要你做什么"。
> 来源：[ENGINE.md](ENGINE.md)（架构迁移 E0–E8）、[VISION.md](VISION.md)（玻璃盒 G、AI 原生 A、算法 O、物理 S、制造 F）、[adr/](adr/)（已接受的决定）。
> 状态栏：⬜ 未开始 ▶ 进行中 ✅ 完成。 规模：**S** 约半天内、**M** 约一两天、**L** 多天或需要调研。

## 0. 通用约定

### 完成的定义（Definition of Done）
每张卡完成时必须同时满足：
1. `pnpm check`、`./scripts/test-python.sh`、`svelte-check` 全绿；新增行为有测试（不是只有"能跑"）。
2. **验收条件逐条有证据**（测试名、命令输出或数字），写在提交信息或 `docs/EXPERIMENTS.md` 里。
3. 触及 schema → 同时给**迁移函数和往返测试**；触及用户可见文字 → 走 i18n 消息键（E1 之后）。
4. 任何**数值结论**写进 `docs/EXPERIMENTS.md`，**含否定性结果**，并标明"模型内"还是"实测"。
5. 影响架构的改动同步更新对应 ADR（状态或"后果"小节）和本文件的状态栏。
6. 提交信息用 Conventional Commits；**不对外发布**（npm、Pages、博客、打印导出）除非任务卡明确写了并由你确认。

### 诚实规则（项目的底线）
猜测的物理参数必须有名字并标 `assumption`；没验证的写"未验证"；发现旧结果有误要**回头更正**并留痕；优化目标要附"防钻空子"压力测试。

```
         │                       │               │                            └─► O 优化工具箱
         └─► E0-03 运动学语料库 ───┘               └─► E5 出处/缓存/作业 DAG ──► G 玻璃盒（实时部分）

```
