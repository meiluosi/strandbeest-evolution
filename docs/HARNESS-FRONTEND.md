## 1. 产品目标与边界

将现有风力兽设计、演化、仿真、制造、测量与可视化能力，组织为一条可复现、可追溯的模型实验旅程：

```text
研究问题与协议 → 有来源的轨迹 → 冻结 Snapshot 与分组切分
    → 基线和学习模型 → Checkpoint 与 ModelArtifact
    → 一步／自由滚动评测 → 参考与预测叠加回放
    → 比较、失败分析与限定结论 → 人工决定下一步
```

首个正式出口是 M0＋M1：不依赖 LLM，人工驱动一个小模型真实实验。模型不优于基线、证据不足和物理验证未完成均是有效结果。M3 才接受控 Research Agent，首版不做无人值守研究、实体设备自动控制或通用 MLOps。

本轮是整体产品展示与交互重构，但不是重写 Beest Engine，也不是用静态概念稿替代真实应用。

## 2. 信息架构

### 2.1 全局 Shell

Shell 持续回答四个问题：

1. 正在看哪个研究项目、实验及不可变修订？
2. 当前设计与场景是什么，是否为预览或已冻结输入？
3. 当前页面展示的是真实执行、历史回放、静态烘焙还是契约样例？
4. 后端、预算和写入权限是否允许当前操作？

全局上下文分为两层：

- **研究上下文**：Program、Experiment、ExperimentRevision；仅在实际选中对象后出现。
- **领域上下文**：现有 Design、Scenario、Run 及其本地编辑状态；不要求每次设计都先填写完整研究协议。

顶栏承载对象上下文、环境状态、语言、主题与上下文命令。侧栏分为：

- **研究**：实验设计、运行与回放、比较与证据。
- **领域工作台**：设计、演化、仿真。
- **更多能力**：资产、制造、数字海滩、实验室。

研究视图是同一实验的三个观察面，不是三套互相复制的列表。移动端保持当前对象、主导航和主操作可达，不能仅靠 hover 或隐藏侧栏发现功能。

### 2.2 深链与兼容

保留现有 `?tab=design|evolve|sim|fab|beach|lab`。新增研究路由可使用：

```text
?tab=research&view=protocol|runs|evidence
    &experiment=<id>&revision=<immutable-revision>
```

路由只保存可分享的对象身份与 UI 视图，不保存完整实验文档、授权或秘密。缺少对象时进入真实空态或创建流程；不能用 `latest` 代替冻结修订。静态构建可分享实际烘焙对象，但不能生成看似已提交的实验地址。

## 3. 三个关联研究视图

### 3.1 实验设计

首屏聚焦研究问题与比较关系，而非完整 Schema 表单堆叠：

- 问题、预期观察与适用范围。
- 来源 Run／Measurement、Design 与 Scenario 的精确引用。
- DatasetSnapshot、SplitManifest、分组和泄漏检查。
- Condition、Trial、基线、学习模型及控制变量差异。
- 评测 Suite、资源预算、权限和冻结修订摘要。

常用路径允许复用已有协议；独立复验明确创建新 Trial，不因配置相同被缓存吞掉。高级字段渐进披露，但所有科学输入最终来自可执行 Schema。

### 3.2 运行与回放

运行区按逻辑 Job 展示数据、训练、评测和汇总 DAG，同时区分 Trial 与 Attempt：

- 状态、进度、当前 Attempt、恢复点、失败类别和实际成本来自服务端。
- 取消先显示 `cancel_requested`，不能立即伪称进程已终止。
- 浏览器刷新或断线后从持久化状态恢复，不重复提交，不把浏览器内存当真相。
- 只有产物完整提交后才显示成功；缓存复用明确指向历史结果，不增加独立样本数。

回放复用 `ReplayViewport`、统一时钟、事件、足端、能量和 A/B 能力，新增：

- 参考轨迹与模型预测的可区分图层、偏差和适用图例。
- 首次发散、落脚、停转和预测异常的时间定位。
- 从异常定位 episode、模型制品、输入 Snapshot 与评测定义的血缘视图。
- 缺失通道、NaN、停转和未验证的独立表达，不把缺失画成零。

“潮汐巨构”环境仍是可关闭的展示层，与预测、参考和物理证据无关。

### 3.3 比较与证据

比较围绕研究问题组织，不建立通用排行榜替代证据：

- 基线与学习模型、不同 Condition、场景、设计族和独立 Trial 的指标。
- 明确样本分母、失败清单、不确定性、测试／开发集边界和统计方法。
- 分开显示执行成功、数值检查、证据等级、Claim 与用途许可。
- 每项结论可回到实际 Run、Artifact、EvaluationRun 和来源边。
- 上游撤回后显示“待复核”及影响范围，不抹除历史判断。
- M3 的 Research Proposal 默认只读；审批前展示成本、范围和协议差异，提案不等于授权。

## 4. 领域工作台重构约束

- **设计**：继续以机构画布和参数检查器为主；所有修改走 Operation 日志。被实验引用时显示精确内容身份，后续编辑不能改变已冻结实验。
- **演化**：继续由真实 Worker 驱动；GA 与 MAP-Elites 分区。演化结果进入实验时保留设计分支与实现身份。
- **仿真**：继续由场景契约和真实 Replay 驱动；后端、WASM 和静态来源可识别。预测图层与原有 A/B 不混用标签。
- **制造／实验室**：统一 Shell、视觉 Token、状态与响应式，但不借展示重构扩大物理或制造结论。
- **数字海滩**：保留入口并明确其规则模型边界；美术效果不能暗示已接入共享物理世界。

## 5. 前端模块与状态主权

建议在实际需要时逐步形成以下边界，不预先创建空目录或六套前端服务：

```text
App Shell / research navigation
    ├─ existing domain workspaces
    ├─ research view compositions
    │    ├─ protocol
    │    ├─ runs + replay
    │    └─ comparison + evidence
    └─ harness API adapters → typed read models / commands
```

- 新增 Harness 访问集中在 API 适配层；组件不直接拼接散落请求或自行推导 Job 成功。
- TypeScript 类型由公共 Schema／生成机制或明确 API 映射获得。展示 ViewModel 可以组合数据，但不能成为科学对象的第二事实源。
- Design 仍归 `editor.svelte.ts`，GA 仍归 `Evolver.svelte` 与 Worker，Replay 时间仍归 `ScenePlayer.svelte`。
- Experiment、Job、Attempt、Artifact、Evaluation 与 Claim 归服务端。前端草稿需区分未提交、已接受、执行中和已提交。
- 语言、主题和面板偏好是 UI 状态，不写入 Design Operation 或 ExperimentRevision。
- 只有确实跨页面共享的选择上下文才提升；不建立包罗万象的 `productStore` 或 `harnessStore`。
- Three.js 与训练相关页面按需加载；新增依赖必须有具体理由和锁定版本。

## 6. 视觉与交互系统

### 6.1 视觉语言

延续“精密机械图纸 + 现代实验仪器 + 少量海滩生命感”，升级为清晰的研究仪器：

- 沙色中性表面与暗色对应主题，铜橙色仅用于当前选择和主操作。
- 冷色用于比较、预测和次级观测；同一语义在图表、回放和指标中一致。
- 细分隔、留白、字号与布局表达主次，避免所有内容卡片化。
- 数字、ID、哈希和单位使用等宽字体；长引用可复制、可截断但不能失去完整读取方式。
- 明月、星空和巨构仅服务 3D 场景，不在数据面板添加无意义粒子、辉光或循环动效。

### 6.2 状态与证据

颜色不能独自承担含义。执行、检查、证据和用途许可使用不同图标、文字与语义 Token：

- 执行：等待、运行、取消请求、失败、成功。
- 检查：通过、失败、未执行、未验证。
- 证据：实际等级、适用范围和撤回／待复核。
- 权限：只读、可提交、需审批、静态不可用。

负结果不使用误导性的成功绿色；工程成功也不自动提升证据等级。

### 6.3 响应式与可访问性

- 1440 保留完整 Shell 和主画布／检查器；1024 收紧次要信息；768 转为可切换单列；375 保持主任务与比较可读。
- 键盘可完成导航、编辑、运行控制、seek 与证据追溯；焦点清晰，图标按钮有可访问名称。
- 中英文、明暗主题和 `prefers-reduced-motion` 同步检查。动画只解释状态变化，物理运动只由真实相位或 Replay 时间驱动。

## 7. live、static 与故障语义

| 场景 | 允许行为 | 禁止行为 |
|---|---|---|
| live | 查询真实对象、提交草稿、经授权启动与取消、重连恢复 | 前端直接改正式状态或伪造授权 |
| static | 展示真实烘焙实验／Run、回放与证据，复制公开引用 | 假装训练、审批、保存或取消成功 |
| 后端离线 | 保留本地设计与已有只读内容，说明受影响能力 | 将旧任务标成仍在实时运行 |
| 契约样例开发 | 组件测试与明确标注的工程预览 | 作为正式研究验收或科学数据 |
| 缺证据／负结果 | 显示缺口、失败分母、限制和可追溯来源 | 改成通过、零误差或隐藏样本 |

## 8. 实施顺序与依赖

HF 卡是 HN06 的前端分解，不替代 HN01–HN08 的后端与契约工作：

1. **HF-00**：基线、现状盘点与接口差异。
2. **HF-01**：Shell、设计系统、导航和兼容深链。
3. **HF-02／HF-03**：现有领域工作台与次级模块整体重塑，可分别验收。
4. **HF-04**：实验协议、Snapshot 与血缘；完整验收依赖 HN01／HN02。
5. **HF-05**：执行、恢复与预测回放；完整验收依赖 HN03／HN04 和 HF-03。
6. **HF-06**：比较与证据；完整验收依赖 HN05。
7. **HF-08**：M1 真实端到端、静态与完整浏览器矩阵。
8. **HF-07**：受控研究提案与审批，属于 M3，依赖 HN07，不阻塞 M1。

后端未就绪时可完成通用界面和真实空态，但对应卡保持进行中，不能用占位数据标记完成。

## 9. 完成定义

除 `ACTIONS.md` 的通用 DoD 外，本轮完整交付至少要求：

- 旧导航和全部现有核心流程无回归；live/static、中英文、明暗主题与四档宽度有浏览器证据。
- 新科学界面无伪造数据、伪执行、伪授权或伪证据；无数据、离线、失败和未验证均可读。
- M1 使用真实来源轨迹、不可变 Snapshot、实际权重与真实评测输出完成一次端到端实验。
- 回放异常能追溯到对应输入、模型、评测与来源；参考／预测共享时间且标签明确。
- 控制台无新增错误，资源无新增 404；浏览器范围明确为固定 Linux Chromium，未测浏览器不得宣称通过。
- 架构、ADR、任务状态和交接记录同步；科学结论与物理门槛另按 VALIDATION 和 EXPERIMENTS 记录。
